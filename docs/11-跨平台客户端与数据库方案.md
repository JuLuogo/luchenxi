# 11 · 跨平台客户端与本地数据库方案（v4 规划）

> 目标（用户需求）：**两套独立客户端**（教师端 / 学生端），**推送到 GitHub 自动构建**出可安装的
> **桌面端（Windows/macOS/Linux）与 Android**（iOS 后期），教师端数据**落在教师机本地 SQLite**（不再依赖浏览器
> localStorage），技术栈尽量「套壳」而非原生开发，并**把 EasyTier 组网缝进应用**（含使用 `--config-server`
> 第三方配置服务器组网的能力）。
>
> 本文是**实施方案**（阶段划分、选型理由、库表设计、EasyTier 集成方式、CI 矩阵与风险）。
> 现状（v3 Web 版）见 [01 架构](01-项目现状与架构.md) 与 [10 多端协同架构](10-多端协同架构.md)。

## 1. 结论先说（选型）

| 维度 | 选择 | 理由 |
| --- | --- | --- |
| 客户端外壳 | **Tauri v2** | 一套前端 + 一套 Rust 后端即可产出 Windows/macOS/Linux/Android（iOS 也已支持）；安装包小（Electron 的 1/10）；**原生支持把外部二进制作为 sidecar 打包**（正好用来缝合 `easytier-core`）；内置 SQLite 能力（`rusqlite`/`sqlx`）无需自带数据库进程 |
| 前端 | **复用现有 HTML/CSS/JS**（`admin.html` / `student.html` / `index.html` + `assets/`） | v3 的界面、状态机、判分逻辑、学情分析已经写好并有 153 项逻辑断言 + 110 项浏览器端到端断言；换壳不重写界面 |
| 教师端后端 | Rust（`hub`：axum + tokio WebSocket；`db`：rusqlite） | 枢纽原来跑在 Node 上；装成桌面 App 后教师机不该依赖 Node 运行时，把 hub + DB 一起塞进 Rust |
| 教师端数据库 | **SQLite**（单文件，随 App 数据目录） | 需求明确要求；便于备份（一个文件）、便于导出 JSON 兼容现有备份格式 |
| 组网 | **EasyTier**（`easytier-core` 作为 sidecar） | 开源 Apache-2.0；有各平台预编译 CLI；支持共享节点/去中心化/`--config-server` 托管 |
| 构建发布 | **GitHub Actions**（`tauri-action` + Android 任务） | 与「推送到 GitHub 就出安装包」的需求一致；本机不需要装 Rust/Android SDK |

**为什么不是 Electron + Capacitor**：Electron 只能桌面，Android 要另起 Capacitor，等于维护两套外壳与两套原生桥；
体积大（~150MB 起）、SQLite 要编译原生模块；而 Tauri 一套代码覆盖四个平台、sidecar 机制天然适合内置 EasyTier。
代价是**需要 Rust 工具链**（见 §7 前置条件）。

## 2. 目标形态

```
教师机（Windows/macOS/Linux 桌面 App，Tauri）
├─ 前端：现有 admin.html 全部功能（7 个页签）
├─ Rust：SQLite（课堂数据主库）+ 内置枢纽（房间/角色/命令转发，协议 v3 不变）+ EasyTier 管理
└─ sidecar：easytier-core（随包分发，可选启用；也可只用局域网）

学生设备
├─ Android App（Tauri Android，只跑 student.html：入座/答题/抢答/看板）
├─ 桌面/其它设备：浏览器打开 教师机 /join（现有方式，继续支持）
└─ 组网：同一局域网直连，或 EasyTier 官方 Android App 组网后连教师机虚拟 IP
```

关键点：**协议不变**。v3 的 `welcome/state/dump/cmd/presence/ack` 报文、房间与角色模型全部保留，
只是服务端从 `sync-server.js`（Node）换成 Rust 内置 hub；大屏 `index.html`、学生端 `student.html` 不用改代码。

## 4. 数据层：SQLite 设计

### 4.1 文件位置与备份

| 平台 | 路径（Tauri `app_data_dir`） |
| --- | --- |
| Windows | `%APPDATA%\luchenxi\classroom.db` |
| macOS | `~/Library/Application Support/luchenxi/classroom.db` |
| Linux | `~/.local/share/luchenxi/classroom.db` |
| Android | 内部存储 `databases/classroom.db`（学生端不需要库） |

- 备份 = 复制该 `.db` 文件；同时保留**导出 JSON**（与 v3 备份格式 `{type:'ci-backup', version, state}` 一致），
  这样网页版 ↔ App 可以互相导入导出（迁移路径不断）。
- 启用 WAL（`PRAGMA journal_mode=WAL`）与 `foreign_keys=ON`。

### 4.2 表结构（与现有 state 一一对应）

```sql
-- 元信息与设置
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT);           -- schema_version / updated_at / rev
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT);       -- courseName, halfRatio, wrongPenalty, fastBonus,
                                                               -- weakThreshold, strongThreshold, minSample, quickCountsAsAttempt
-- 分组与人员
CREATE TABLE tiers (key TEXT PRIMARY KEY, label TEXT, weight REAL, color TEXT, descr TEXT, sort INTEGER);
CREATE TABLE tags (name TEXT PRIMARY KEY, sort INTEGER);
CREATE TABLE teams (id TEXT PRIMARY KEY, name TEXT, icon TEXT, color TEXT, sort INTEGER);
CREATE TABLE students (id TEXT PRIMARY KEY, name TEXT, team_id TEXT REFERENCES teams(id), active INTEGER DEFAULT 1, joined_at INTEGER);
-- 题库与试卷
CREATE TABLE questions (id TEXT PRIMARY KEY, tier TEXT, points REAL NULL, stem TEXT, answer TEXT,
                        options TEXT,               -- JSON 数组
                        tags TEXT,                  -- JSON 数组
                        source TEXT, note TEXT, archived INTEGER DEFAULT 0, created_at INTEGER);
CREATE TABLE quizzes (id TEXT PRIMARY KEY, name TEXT, note TEXT, created_at INTEGER, closed_at INTEGER DEFAULT 0,
                      question_ids TEXT,            -- JSON 数组，顺序即答题顺序
                      kind TEXT DEFAULT 'normal'); -- normal | collector(快捷记分) | legacy(v1 迁移)
-- 积分流水（唯一事实来源；学生积分 = SUM(points)）
CREATE TABLE records (id TEXT PRIMARY KEY, sid TEXT, qid TEXT NULL, tier TEXT, quiz_id TEXT NULL,
                      result TEXT, base REAL, ratio REAL, points REAL, source TEXT, note TEXT, at INTEGER, by_who TEXT);
CREATE INDEX idx_records_sid ON records(sid);
CREATE INDEX idx_records_quiz ON records(quiz_id, at);
CREATE INDEX idx_records_qid ON records(qid, sid);
-- 课堂过程数据（v3 的 state.classroom）
CREATE TABLE classroom_pending (id TEXT PRIMARY KEY, sid TEXT, team_id TEXT, qid TEXT, quiz_id TEXT,
                                answer TEXT, auto INTEGER DEFAULT 0, at INTEGER);
CREATE TABLE classroom_buzz (id TEXT PRIMARY KEY, team_id TEXT, qid TEXT, sid TEXT, at INTEGER, by_who TEXT);
CREATE TABLE classroom_feed (id TEXT PRIMARY KEY, at INTEGER, kind TEXT, team_id TEXT, sid TEXT, qid TEXT,
                             result TEXT, answer TEXT, points REAL, auto INTEGER, text TEXT);
-- 点名
CREATE TABLE roll_history (id TEXT PRIMARY KEY, sid TEXT, at INTEGER, quiz_id TEXT, qid TEXT);
CREATE TABLE roll_state (key TEXT PRIMARY KEY, value TEXT);      -- mode/scope/excludeAnswered/recentExclude/roundPool/round
-- 运行上下文与日志
CREATE TABLE runtime (key TEXT PRIMARY KEY, value TEXT);          -- quizId/qid/sid/accepting/reveal/revealedQid
CREATE TABLE logs (id INTEGER PRIMARY KEY AUTOINCREMENT, ts INTEGER, type TEXT, detail TEXT);
```

**性能**：`scoreOf` 由 `SUM(points)` 直接算（有索引），比现在遍历流水更快；学情统计可下推到 SQL
（`GROUP BY tier, sid`），破万条流水也不卡。

### 4.3 前端零改动：存储适配层

现有 `store.js` 的读写集中在少数几个函数（`load/save/commit/tx`）。改造方式：

```js
// packages/core-web/storage.js
CI.storage = {
  async init(),            // 建库/迁移
  async loadState(),       // 返回与现在同构的 state 对象（一次 SELECT 组装）
  async commit(patch),     // 差量写：{records:[…], students:[…], …}
  async exportJSON(),      // 兼容 v3 备份
  async importJSON(backup)
};
```

- 浏览器实现：`localStorage`（现状，保持可用）；
- Tauri 实现：`invoke('db_load_state')` / `invoke('db_commit', {patch})`；
- Rust 侧保持**同一个 state 形状**做序列化，前端业务代码（判分、学情、点名、题库）**一行不改**。

## 5. 内置枢纽（Rust 替换 Node）

- 技术：`axum`（HTTP 静态资源 + `/health` + `/qr.png`）+ `tokio-tungstenite`/`axum::extract::ws`（WebSocket）。
- 复用 v3 协议：房间、`host/stage/team` 角色、`state/dump/request/request-dump/cmd/ack/presence/cmd-backlog`。
- 监听 `0.0.0.0:<port>`（默认 8080，可在 App 设置里改），打印/展示局域网地址与二维码。
- 与 SQLite 同进程：`state` 由 DB 派生 + 内存缓存，`dump` 落 `rooms/<房间>.json`（或直接存 DB 的 `room_dumps` 表）。
- **学生端不感知**：它仍然只说 v3 报文。

## 6. EasyTier 缝合方案

### 6.1 桌面端（可行，sidecar 内置）

已就位的工程件：`scripts/fetch-easytier.mjs`（按 target-triple 下载官方 Release 并改名成 Tauri 约定）、
`apps/teacher/src-tauri/tauri.conf.json` 的 `bundle.externalBin`、`crates/ci-core/src/net.rs`
（参数拼装 + 进程管理 + `easytier-cli` 状态查询）。

1. 构建时按平台放入对应二进制（[EasyTier Release](https://github.com/EasyTier/EasyTier/releases) 的 CLI 压缩包内
   `easytier-core` / `easytier-cli`）：`src-tauri/binaries/easytier-core-<target-triple>[.exe]`，
   在 `tauri.conf.json` 的 `bundle.externalBin` 中登记 → 随安装包分发。
2. App 内「组网」面板（新增页签）：
   - 基础模式：`easytier-core -d --network-name <名> --network-secret <密钥> -p tcp://public.easytier.cn:11010`
     （`-d` DHCP 自动取虚拟 IP；教师机也可用 `-i 10.144.144.1` 固定 IP）
   - 多共享节点：支持填多个 `-p`（容灾）
   - 手动指定监听端口（`-l`）避免多开冲突
   - 状态查询：调用 `easytier-cli node|peer|route` 并解析成界面表格
3. **第三方配置服务器（用户提到的能力）**：`easytier-core` 支持 `-w <用户名>` / `--config-server <URL>`，
   即可由 **EasyTier Web 控制台**（官方 `https://easytier.cn/web` 或**自建 `easytier-web`**）下发配置。
   App 里提供「托管模式」输入框：配置服务器地址 + 用户名（可再加自建服务器说明）。
   > 说明：官方文档只描述了「官方 Web 控制台 / 自建 easytier-web」两种托管方式；用户提到的 “Easy PRO” 属于第三方服务，
   > 我无法核实其接口，方案里按**支持任意 `--config-server` 地址**来设计，第三方只要兼容该协议就能用。
4. 权限与平台差异：
   - Windows：需要管理员或安装 Wintun（TUN 模式）；也可用**无 TUN 模式**（免 Root，仅代理流量）
   - macOS：首次需授权网络扩展/管理员
   - Linux：root 或 `CAP_NET_ADMIN`，或用无 TUN 模式
   → App 内做前置检查 + 一键提权引导，失败时回退到「仅局域网」并提示。

### 6.2 Android 端（有硬限制，必须说明）

- EasyTier 官方 **Android 只有 GUI APK，没有 CLI 版**（见[下载页](http://doc.easytier.cn/guide/download.html)的
  “Android / universal / apk”一行），因此**无法把 `easytier-core` 作为 sidecar 打进我们的 Android 学生端**。
- 现实可行的三条路：
  1. **同一局域网直连**（推荐，教室场景最常见，零配置）；
  2. 学生先在手机上装 **EasyTier 官方 App** 加入同一虚拟网，再用我们的学生端连教师机的虚拟 IP
     （App 内提供图文引导与「连通性自检」按钮）；
  3. 后期若需要「一体化」，只能自己编译 EasyTier 的 Android 库（Rust `cdylib` + JNI，工程量另计，作为 P4 之后的备选）。
- iOS 同理（且需要 Mac + 开发者证书）。

## 7. 构建与发布（GitHub Actions）

| 工作流 | 触发 | 产物 |
| --- | --- | --- |
| `test.yml` | push / PR / 手动 | 调用 `scripts/ci-local.mjs`：产物生成 → 十组断言 → 文档审计 → 两条浏览器端到端 |
| `build.yml` | tag `v*` 或手动 | Windows `.msi`、macOS `.dmg`、Linux `.deb`/`.AppImage`（教师端 + 学生端），Android `.apk`；iOS 为编译检查（`continue-on-error`） |

| `demo.yml` | **仅手动** | 跑 `tests/demo.js`（整堂演示）并把 `docs/demo` 截图与实录上传为 artifact |

> 说明：`build.yml` 直接跑客户端的 `npm run build`（= tauri build）并 `tee` 日志，，tag 时用 `softprops/action-gh-release` 挂 Draft Release，不需要单独的 `release.yml`。
> **首次实跑（v4.0.0）已发现并修掉的问题**见 [apps/README.md](../apps/README.md) 的"首次 CI 实跑结果"一节。
> 四个工作流的键名与结构都由 `tests/ci.test.js` 用官方 workflow schema 校验（见 §8.0）。

要点：
- 引擎矩阵：`windows-latest` / `macos-14`（arm64，可同时出 x64）/ `ubuntu-22.04`（出 deb+AppImage）；
  Android 用 `ubuntu-latest` + `android-actions/setup-android` + NDK（Tauri v2 官方支持）。
- Rust 侧缓存（`Swatinem/rust-cache`）、Tauri 缓存（`tauri-apps/tauri-action`）。
- **签名**：Android 需自建 keystore（存 GitHub Secrets）；macOS 不做公证（未签名 App 首次需右键打开）；
  Windows 不买证书时会有 SmartScreen 提示。这些会在发布说明里写清楚。

### 8.0 客户端工程已补齐的构建前置条件

### 8.1 能力对照：网页版 vs 客户端（同一份前端，两种外壳）

| 能力 | 网页版（v3） | 客户端（v4） | 说明 |
| --- | --- | --- | --- |
| 记分 / 题库 / 组卷 / 点名 / 学情 / 大屏 | ✅ | ✅ | **同一份前端代码**（`scripts/sync-ui.mjs` 复制），功能不分叉 |
| 数据存储 | 枢纽机的 `data/classroom.db`（经 `/api/state`）；浏览器 localStorage 作镜像 | App 数据目录的 `classroom.db`（`invoke` 直连）；localStorage 仍作镜像 | 客户端不依赖浏览器存储；换设备只需拷 `.db` 或导出 JSON |
| 枢纽进程 | 需老师手动起 `node sync-server.js`（或双击「启动课堂.cmd」） | **App 启动即内置枢纽**（Rust，同协议），无需 Node | 学生端与大屏接入方式完全一致 |
| 学生端 / 大屏接入 | 浏览器 `http://<IP>:8080/join`、`/stage` | 浏览器同样可用；另可装 Android 学生端 | 协议未变，可混用（有的学生用浏览器、有的用 App） |
| 二维码 | 枢纽提供 `/qr.png` | **无 `/qr.png`** → 面板自动降级为文字地址（可复制） | 已知差异：客户端里用「复制地址」发给学生；后续可选在 Rust 侧加 `qrcode` crate 补齐 |
| 组网（跨网段） | 需另装 EasyTier | **内置 `easytier-core` sidecar**，⑦ 页一键组网 + `--config-server` 托管 | 仅桌面端；Android 官方无 CLI，走官方 App 引导 |
| 写入可靠性 | 落库失败时页面仍在，重开即恢复 | 落库失败**退避重试 4 次**；关页/切后台立即 `flush()`；失败时顶栏红字写明"数据没丢" | 多写者下带 `rev` 的过期写入会被枢纽以 **409** 拒绝，不覆盖新数据 |
| 单机模式 | 双击 `admin.html`（file://）→ 回落 `ws://localhost:8080` | 内置换落本机枢纽，天然单机可用 | 两种情况都保证记分/点名/组卷/学情照常 |
| 安装与更新 | 无需安装 | 安装包（`.msi`/`.dmg`/`.deb`/`.apk`），可离线运行 | 出包走 GitHub Actions（`build.yml`） |

> 取舍原则：**能共用的都共用**（前端、协议、数据格式、备份 JSON），只在"浏览器做不到"的地方分叉
> （本地数据库、内置枢纽、sidecar 组网、安装包）。

## 9. 风险与待定决策

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 本地无 Rust/Android 工具链 | 我无法在本机编译验证，只能靠 CI | 每个阶段都写「CI 能过」的校验；必要时你在本机装 rustup 后本地跑一次 |
| Tauri Android 生态仍在演进 | 个别插件不支持 Android | 学生端只依赖 HTTP/WebSocket 与本地存储，不用复杂插件 |
| EasyTier 需 TUN/提权 | 学生手机不一定能给权限 | 优先局域网直连；EasyTier 只作为「跨网」可选增强 |
| 未签名安装包 | 用户首次安装有安全提示 | 发布说明写明操作；后期可买证书/公证 |
| 协议漂移（Rust 与 JS 两端） | 联调踩坑 | `packages/protocol` 单一来源生成两端结构；e2e 用例兜底 |

## 10. 与现有网页版的关系

- 网页版**不废弃**：`pnpm start` + 浏览器仍是「零安装」兜底；教师临时借用别人电脑时最有用。
- App 版是正式形态：教师端 SQLite + 内置枢纽 + 组网；学生端 Android 装机即用。
- 两者数据互通：备份 JSON 格式一致（`ci-backup` v3），网页版导出的数据可直接导入 App。
