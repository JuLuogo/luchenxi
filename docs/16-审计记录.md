## 4. 我自己反复踩的坑（写下来免得再犯）

1. **在 JS 脚本里生成 Rust/JS 代码时的引号冲突**（踩 4 次）：外层 `"..."` 里又放 `"`，
   或 Rust 文档注释里的反引号把 JS 模板串提前结束。**规则**：内层一律用「」，
   外层用单引号；不写反引号。
2. **按行 splice 的替换区间算错**（踩 4 次）：多删一行、少删一行、把代码插进结构体里。
   **规则**：对函数体这类有明确边界的东西，**整段重写**（找函数头 + 配对的 `}`），
   不要"插几行 + 删一行"；每次改完立刻 `node --check` / `vue-tsc`。
3. **注释插错块**：给 `StoragePage` 插了 HTML 注释，但那一行在 `<script setup>` 里。
   **规则**：先看这一行在**哪个块**（template / script / style）。
4. **写环境相关的断言**：断言 `doctor` 退出码必须为 0 —— 而 CI 上缺 JDK/Android SDK
   本来就会返回 1。**规则**：断言"当初那个 bug 的特征"（这里是崩溃码），
   而不是"我机器上的结果"。

## 6. 第二轮审计新增发现（2026-10-05）

### 6.1 每个学生都能读到全班数据（**已修复**，第 8–9、21–23 轮）

学生端收到的是**完整快照** `payload`（`assets/js/student.js` 的 `payload` 变量），
`CIStudent.state()` 也把它原样暴露 —— 而 `docs/09` 的设计原则是
"个人成绩只发给学生自己的手机"。

**现状**：一个学生打开控制台就能读到全班所有人的分数、错题、评语。
**影响**：与"不公开排名"的决策自相矛盾（大屏已经拿掉个人榜，但数据本身还在每个学生手里）。
**实际怎么修的（四层，两个枢纽同口径）**：

| 层 | 做了什么 | 轮次 |
| --- | --- | --- |
| ① 定义边界 | `CI.classroom.publicPayload()` —— "学生/大屏该看到什么"，并用测试钉住 | 8 |
| ② 清掉排名表 | 广播里不再带 `score`/`rank`/`level`/`weakTiers` 与 `ability.students`、`missers` | 9 |
| ③ 按角色下发 | `host` 全量 ｜ `stage` 只有身份 ｜ `team` **只收本队成员** | 21–22 |
| ④ 成绩边界 | **本队成员的成绩可见**（学生端三处 UI 要用）、**大屏不投个人分数** | 23 |

**②的一个副作用（第 23 轮发现并修回）**：第 9 轮把成绩字段全删了，
而学生端的「我得分 / 我答对 / 能力画像」三处 UI 正是读这些字段 ——
于是它们**静默变成 0 / 空**（两条 e2e 都没断言这三处）。
正确做法是"**字段留着、边界由枢纽守**"，已在第 23 轮改正。

**验证**：黑盒测试 24 项 × 两个枢纽，其中 7 项专门盯这条边界（第 22–23 轮）。

### 7.3 API 规范（两版枢纽对齐）

- 请求体上限对齐（Node 16MB ↔ Rust `DefaultBodyLimit`）

### 7.5 第二轮学到的（比第一轮更重要）

1. **"改完必须看图"** —— 颜色迁移在测试上完全通过，但界面上把一个图表弄坏了。
2. **语法通过 ≠ 模块正常** —— 我零散改 `student.js` 五处，`node --check` 通过、
   `require` 不抛错，但 **`CIStudent` 一个导出都没有**，功能全静默失效。
   所以有了 `domain-load-check.cjs`。
3. **`git checkout -- <file>` 会把你这一轮做好的改动一起丢掉** ——
   我因此把已经加好的 stage 裁剪回退掉，然后花十几轮排查"为什么不生效"。
   **先确认代码在不在文件里，再怀疑逻辑。**
4. **测试失败时先分清"代码错了"还是"测试写错了"** ——
   有一次是后者（我用 `hello` 提权连接，等于自己演了一遍攻击），
   如果直接去"修"代码，会把**防冒名**这个高危修复拆掉。
5. **锚点唯一性要显式确认** —— 同一个字符串在文件里出现多次时，
   按文本匹配必然改错（我踩了 5 次）。
