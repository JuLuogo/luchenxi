**关键经验**：子代理深审的产出质量取决于**给它们的约束**。有效的写法是
"只审计、不修改"+"每条给文件:行号 + 具体触发输入 + 建议修法 + 严重程度"+
"没问题的文件也要明说"。这样得到的报告可直接照做，且能区分"真问题"与"风格建议"。

## 4. 我自己反复踩的坑（写下来免得再犯）

1. **在 JS 脚本里生成 Rust/JS 代码时的引号冲突**（踩 4 次）：外层 `"..."` 里又放 `"`，
   或 Rust 文档注释里的反引号把 JS 模板串提前结束。**规则**：内层一律用「」，
   外层用单引号；不写反引号。
2. **按行 splice 的替换区间算错**（踩 4 次）：多删一行、少删一行、把代码插进结构体里。
   **规则**：对函数体这类有明确边界的东西，**整段重写**（找函数头 + 配对的 `}`），
   不要"插几行 + 删一行"；每次改完立刻 `node --check` / `vue-tsc`。
3. **注释插错块**：给 `StoragePage` 插了 HTML 注释，但那一行在 `<script setup>` 里。
   **规则**：先看这一行在**哪个块**（template / script / style）。
4. **写环境相关的断言**：断言 `doctor` 退出码必须为 0 —— 而 CI 上缺 JDK/Android SDK
   本来就会返回 1。**规则**：断言"当初那个 bug 的特征"（这里是崩溃码），
   而不是"我机器上的结果"。

## 6. 第二轮审计新增发现（2026-10-05）

### 6.1 每个学生都能读到全班数据（待处理）

学生端收到的是**完整快照** `payload`（`assets/js/student.js` 的 `payload` 变量），
`CIStudent.state()` 也把它原样暴露 —— 而 `docs/09` 的设计原则是
"个人成绩只发给学生自己的手机"。

**现状**：一个学生打开控制台就能读到全班所有人的分数、错题、评语。
**影响**：与"不公开排名"的决策自相矛盾（大屏已经拿掉个人榜，但数据本身还在每个学生手里）。
**修法（成本中高）**：枢纽按角色下发 —— team 角色只收到
`{ 本题、本队、自己的记录、班级聚合 }`，host/stage 才拿全量。
需要同时改 `crates/ci-hub`、`sync-server.js`、`student.js` 与 parity 基准。
**优先级**：高（隐私），但改动面大，单独一轮做。
