> 这份文档把"可执行的规则"抄下来，作为本项目 UI 的**验收依据**。
> 原则：**从尺度选值，不要临时拍**（amateur UI 的头号成因是 17px 这种临时值）。

## 1. 五套尺度（选定后不许再发明新值）

### 间距 / 尺寸
```
4  8  12  16  24  32  48  64  96  128  192  256
```
相邻两值至少差 ~25%（这就是"4 的倍数"线性表不够用的原因：120 与 124 之间没法选）。

### 字号
```
12  14  16  18  20  24  30  36  48  60  72
```
**单位只用 px / rem，绝不用 em**（em 会随父级复合，算出 17.5px 这种不在尺度上的值）。
（例外：`max-width` 量行宽时用 em 是对的 —— 行宽该随文字缩放。）

### 字重
只用两档：**400/500**（正文与多数 UI 文字）、**600/700**（强调）。UI 里不用 <400。

### 颜色
- **灰阶 8–10 档**（UI 的绝大部分是灰：文字、背景、面板、边框、控件）
- **主色 5–10 档**，强调色（危险红 / 警告黄 / 正向绿…）各 5–10 档
- 命名 `100`（最浅）→ `900`（最深），基准 `500`
- **用 HSL 写，不用 hex**（`hsl(220,95%,34%)` 与 `hsl(220,65%,61%)` 看得出是同一族）
- **绝不在运行时 `lighten()/darken()` 生成色阶**（那是 35 种略微不同的蓝的来源）

### 阴影（五个高度层）
```css
0 1px 3px  hsla(0,0%,0%,.2)   /* 刚抬起 —— 按钮 */
0 4px 6px  hsla(0,0%,0%,.2)   /* 下拉 */
0 5px 15px hsla(0,0%,0%,.2)
0 10px 24px hsla(0,0%,0%,.2)
0 15px 35px hsla(0,0%,0%,.2)  /* 弹窗 */
```
问"它在 z 轴哪一层"，而不是"哪个阴影好看"。

### 圆角
**选一个并保持一致**。小圆角=中性，大圆角=活泼，无圆角=严肃。混用一定更难看。

### 行高 / 行宽
行高与字号**成反比**、与行宽成正比：小字/宽栏 1.5–2；大标题 1 都行。
行宽 **45–75 字符**（`max-width: 20em–35em`）。

## 2. 层级（最出效果的一条）

一切都在"主要 / 次要 / 三级"金字塔里。全都争抢注意力 = 噪音。

- **别只靠字号做层级** —— 那会让主要文字过大、次要文字过小。用**字重 + 颜色**。
- **文字颜色最多三种**：深（主要）、灰（次要）、更浅的灰（三级）。
  三种都要 4.5:1 —— "更浅的灰"是指**仍然达标的最浅那一档**，不是最浅的那档。
- **靠"弱化别人"来突出重点**：重点元素实在压不住时，去弱化它的竞争者
  （淡掉非活动导航项、去掉侧栏背景色）。
- **动作按层级排，不按语义排**：
  - 主要 → 实心高对比，**一页通常只有一个**
  - 次要 → 描边 / 低对比背景
  - 三级 → 当链接
  - **破坏性 ≠ 大红按钮**。不是页面主操作时给三级样式，
    到确认弹窗里它才是主操作，那时再用红实心。
- **标签是最后手段**：`label: value` 让每条数据等重。格式或上下文能说明的就别加标签；
  要加就把标签并进值里（"还剩 12 件" 而不是 "库存：12"），或让它明显是次要内容。
- **字重与对比度互相补偿**：实心图标视觉更重，把它的颜色调淡来补偿；
  1px 边框太淡就加粗到 2px，而不是加深颜色。

## 3. 硬规则（违反会产生可辨认的失败）

1. **绝不在彩色背景上用灰字**（灰字在白底是"降低对比"，在彩色上只是脏）。
   白字降透明度会显得像禁用、还会透出底纹。要**手挑同色相、调饱和/明度的颜色**。
2. **字号绝不用 em**（px / rem）。
3. **绝不运行时生成色阶**。
4. **不该缩放的东西别用百分比宽度**：侧栏定宽、主区自适应；元素给 `max-width`，
   只在屏幕真的更小时才缩。
5. **跨断点别等比缩放**：大元素要比小元素**缩得更快**。
6. **组外的间距必须大于组内**（"哪个标签属于哪个字段"就是这个 bug；
   项目符号列表的 gap 要大于行高）。
7. **颜色不能是唯一信号**（加图标/形状/文字；图表用**明度**区分而非色相 ——
   色盲用户能可靠读出明暗）。
8. **对比度**：正文 4.5:1；3:1 只适用于**大字**（WCAG 定义 24px 常规或 18.66px 粗体，
   不是 18px）。非文字也要 3:1（WCAG 1.4.11）：**靠边框识别控件时**（输入框轮廓、
   复选框边缘）边框要 3:1；仅用于分隔内容的细线不需要 —— 这是**两个不同的 token**。
9. **图标别远离它该有的尺寸**（16–24px 的图标放到 48px 会又粗又缺细节）——
   放进彩色圆/方块里。

## 4. "症状 → 实际病因 → 修法"对照表（改造现有 UI 时按顺序查）

| 症状 | 实际病因 | 修法 |
| --- | --- | --- |
| 吵、乱、"一堵内容墙"、没有视觉焦点 | 没有层级，所有东西等重 | **主动弱化**次要/三级内容，而不是放大主要 |
| 某个元素怎么都突出不了 | 它的邻居在争抢 | 弱化竞争者（淡掉非活动项、去掉侧栏底色） |
| 挤、憋 | 空间是"加到不难受为止" | 重新从**过多**空间开始，往回减 |
| 分组含糊（哪个标签配哪个字段） | 组内与组间间距相等 | 组外 > 组内；列表 gap > 行高 |
| 框太多、被分割得太碎 | 边框太多 | 换成阴影 / 两级背景色 / 纯靠间距；**边框与背景变化同时存在时，去掉边框**；识别控件的边框保留（且要 3:1） |
| 彩色面板上的字发灰、像禁用 | 灰字或白字降透明度 | 手挑同色相颜色 |
| 主要文字过大**且**次要文字过小 | 全靠字号做层级 | 把强调移到字重与颜色，字号往中间收 |
| 非主操作却是大红按钮 | 按语义而非层级设计 | 破坏性操作给次要/三级样式，红色留给确认弹窗 |
| 页面标题过大、压住一切 | 把 h1 当成 h1 来样式 | 区块标题其实是"标签"，16px 就够 |
| 数据像数据库导出（`姓名:` `邮箱:`） | 天真的 label/value | 去掉格式或上下文已暗示的标签；否则让标签明显次要 |
| 图标压过旁边的文字 | 实心图标覆盖面更大 | 降低图标对比度 |
| 1px 边框要么看不见要么太硬 | 想用颜色解决重量 | 保持软颜色，改成 2px |
| 大图标又粗又糙 | 16–24px 的图标被放大 | 别放大，放进彩色圆里 |
| 布局在大屏上摊得很薄 | "屏幕在那儿所以填满" | 只用内容需要的宽度，或分栏而不是拉长 |
| 大屏侧栏过宽、小屏被截断 | 网格给的百分比宽度 | 侧栏定宽、主区 flex |
| 同一行字号不一看着没对齐 | 垂直居中 | `align-items: baseline` |
| 全大写标签难读 | 默认字距是按句首大写调的 | 加 ~0.05em 字距 |
| 到处都是彩色链接，很吵 | 把正文的链接样式用到了链接密集的 UI | 用字重或更深的颜色强调；真正次要的链接只在 hover 时显现 |
| 长段落居中难读 | 超过 2–3 行还居中 | 左对齐，或把文案改短 |
| 数字列不好比较 | 数字左对齐 | 右对齐 |
| 平、素、"没毛病但也没亮点" | 全无视觉点缀 | 加彩色强调条（卡片顶边、标题下、警告侧边、活动导航项）、换一段背景色、≤30° 双色渐变、低对比纹理 —— 不必铺满，沿一条边也行 |
| 像半成品 | 到处是浏览器默认样式 | 列表符号换图标、复选框/单选框用品牌色、引用做成视觉元素、链接样式独特 |
| 新用户看到空白屏 | 空态是事后补的 | 插图 + 明确标题 + 强调的行动按钮；**把暂时没用的标签/筛选/搜索藏起来** |
| 组件很"通用" | 默认心智模型 | 打破盒子（多列下拉带图标与说明、表格合并列与内联图、单选组做成可选卡片） |
| 元素像贴上去的 | 每个东西都在自己的矩形里 | 叠层（负 margin 让卡片跨两个背景，或伸出父容器边缘） |
| 图表色盲不可读 | 用色相区分系列 | 用**明度**区分（同色系深浅），并给颜色编码的指标加图标/箭头 |
