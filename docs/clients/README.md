## 三套界面 vs 两个客户端壳

```
        ┌──────────────── 三个界面（同一套 Vue 3 代码） ────────────────┐
        │  教师端 /next/admin.html    学生端 /next/join    大屏 /next/stage │
        └───────────┬─────────────────────┬──────────────────┬─────────┘
                    │                     │                  │
        ┌───────────▼──────────┐   ┌──────▼───────┐   ┌──────▼───────┐
        │ 教师端桌面客户端(Tauri)│   │ 学生端安卓 App │   │  浏览器 / 大屏 │
        │ 内置枢纽 + 本机 SQLite │   │ 纯客户端       │   │  只读订阅      │
        └──────────────────────┘   └──────────────┘   └──────────────┘
```

- **三个界面**：`web/` 下的 Vue 3 应用（教师端 Element Plus / 学生端 Vant 移动优先 / 大屏），
  由枢纽挂在 `/next/` 下提供；
- **两个壳**：`apps/teacher`（Windows/macOS/Linux）与 `apps/student`（Android），
  把同一份界面套进 Tauri 窗口，并补上浏览器做不到的能力（本机 SQLite / 内置枢纽 / 组网 / 明文 HTTP）。

## 怎么把系统跑起来（截图就是这么做出来的）

```powershell
npm install
npm start                    # 起枢纽 + 打开教师端（也可双击「启动课堂.cmd」）

# 三端地址
# 教师端（新版 Vue）http://localhost:8080/next/admin.html
# 学生端            http://<教师机IP>:8080/next/join?room=<房间号>
# 教室大屏          http://localhost:8080/next/stage?room=<房间号>
```

> 注意：新版 Vue 界面是**构建产物**，`web/dist` 按惯例不入版本库。
> 克隆下来第一次访问 `/next/` 会是空的，先跑一次 `npm run web:build`。

## 截图与文档是怎么产出的（可复现）

本目录所有截图都是**在真实运行的界面上自动截出来的**，不是手工拼的，也不是静态假图。

| 脚本 | 作用 |
| --- | --- |
| [tests/shots-docs.js](../../tests/shots-docs.js) | 自动起**隔离枢纽**（临时数据库 + 空闲端口）→ 灌入模拟数据 → 打开三套界面 → **按按钮文字真实点击** → 逐页截图 |
| [tests/shot-tauri.js](../../tests/shot-tauri.js) | 通过 WebView2 的远程调试端口，截取**桌面应用窗口内的真实界面** |

```powershell
node tests/shots-docs.js                 # 三套界面全跑
node tests/shots-docs.js --only=teacher  # 只跑教师端（student / stage 同理）

# 桌面客户端：先带调试端口启动应用，再截图
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS='--remote-debugging-port=9333'
Start-Process target\release\luchenxi-teacher.exe
node tests/shot-tauri.js 9333
```

截图输出在 `docs/clients/images/<客户端>/`，附 `manifest.json`（文件名 ↔ 说明）便于核对。

## 本轮实测的结论（一句话版）

| 客户端 | 结论 |
| --- | --- |
| 教师端界面 | ✅ 23 张截图，页面错误 0；发现并修复「当前试卷恒为未选择」与「生成班级小结点了没反应」两个真 bug |
| 学生端界面 | ✅ 12 张截图，页面错误 0；全流程（入座→答题→抢答→公布答案）跑通；发现「抢答无持久反馈」「无倒计时显示」两处体验缺口 |
| 教室大屏 | ✅ 7 张截图，四屏联动正常 |
| 教师端桌面客户端 | ⚠️→✅ 发现**两个真问题**并修复：① 应用打开的是大屏页而非教师端；② 永远连不上自己的内置枢纽（一直单机模式） |
| 学生端安卓客户端 | ⚠️→✅ 全链路跑通（交叉编译 → 打包 → 签名 → **装进 Android 15 模拟器 → 启动渲染**）；发现并修复**两个致命问题**：① 打开是黑屏（`asset not found: index.html`）；② 学生看不到"填教师机地址"输入框、永远连不上。仅"点连接真正连上"这一步未能自动化（模拟器点击不触发 WebView 事件） |

### 本轮改动一览

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `apps/student/src-tauri/tauri.conf.json` | 修 bug | 窗口缺 `url` → 安卓 App **打开就是黑屏**（`asset not found: index.html`） |
| `assets/js/student.js` | 修 bug | `servedByHub()` 把 Tauri 伪源当成枢纽 → 学生端**隐藏了"填教师机地址"输入框** |
| `apps/teacher/src-tauri/tauri.conf.json` | 修 bug | 窗口缺 `url`，桌面应用默认加载了大屏页 |
| `assets/js/sync.js` | 修 bug | `servedOverHttp()` 把 Tauri 伪源当成真枢纽，导致教师端永远"单机模式" |
| `web/src/teacher/pages/AnalysisPage.vue` | 修 bug | `summarizeClass()` 返回对象却当成数组 `.join()` → 「生成班级小结」整个不可用 |
| `web/src/shared/class-store.ts` | 修 bug | `currentQuiz` 漏传 `currentQuizId`，导致「当前试卷」永远是"未选择" |
| `tests/shots-docs.js` | 新增工具 | 三套界面的批量截图驱动（隔离枢纽 + 模拟数据 + 真实点击） |
| `tests/shot-tauri.js` | 新增工具 | 通过 WebView2 调试端口截取桌面应用真实界面 |
| `docs/clients/**` | 新增文档 | 5 篇客户端文档 + 索引 + 51 张截图 + `manifest.json` |

> **一个值得注意的规律**：四个 bug 里有**三个是同一个根因** ——
> Tauri v2 在 Windows/Android 上把前端挂在 `http://tauri.localhost`，而代码里多处
> 把它当成了"真实的 http 源/枢纽源"。三处分别打在三套不同代码上（教师端同步、学生端同步、学生端入座页），
> 建议把"客户端 asset 协议"这个判断在项目里统一收口。

> 未改动但已记录的问题：学生端抢答反馈、学生端倒计时、桌面壳无二维码、桌面壳仍套旧版界面。
> 详见各篇文档的「实测发现」小节。
