# 公开课模式设计（2026-10）

> 公开课是**不能出问题**的场景：有听课老师在、有时间压力、现场无法重来。
> 这份文档先定清楚"要什么、怎么做、什么绝对不做"，再动手。

## 1. 场景与三个核心环节

用户明确的三个最要紧的环节：

| 环节 | 公开课上的实际形态 | 复用什么 |
| --- | --- | --- |
| **随机点名** | "我们请一位同学来回答" —— 公平、随机、当众可见 | 已有 `rollcall`（Rust + JS + parity） |
| **抽题答题** | 抽一道题，学生答；**以客观题为主** | 已有 `draw`（可加题型/标签过滤） |
| **评价** | 老师现场给多维评价 + 一句评语，当众说/展示 | 已有 `ability`/`stats` + **本轮新增公开课量规** |

**主观题怎么处理**（用户明确）：抽到了也不慌 —— 学生答，**老师现场判定**三档：
全对 / 对一半 / 不对。与现有 `recordResult` 的 `correct`/`half`/`wrong` 一致，
`half` 已按 `halfRatio` 折算掌握度。

## 2. 多维度现场评价（公开课量规）

日常课用"正确性/参与度/进步"（数据自动算）；公开课要的是**现场观察判断**，
所以另立一套**四维量规**，每维四档，老师点四下就完事：

| 维度 | 权重 | 看什么（给老师的锚点） |
| --- | --- | --- |
| **基础掌握** | 30 | 概念、公式、常规运算是否准确 |
| **拓展迁移** | 30 | 能否举一反三、把方法用到新情境 |
| **思维表达** | 25 | 思路是否清晰、表达是否有条理 |
| **参与态度** | 15 | 投入程度、回应质量、是否敢试 |

四档：**待改进 / 合格 / 良好 / 优秀**（1–4 分）。

**为什么是这四维**：公开课评课表普遍看"目标达成 / 思维品质 / 参与度 / 表达"
（见 `docs/research/评价算法与量规设计.md` §3）；这四维是它的**学生侧投影** ——
听课老师看的是教师，但现场被点评的是学生，两侧口径要能对上。

**权重可配置**：与"综合表现"同一套设置界面，默认 30/30/25/15。

## 3. 评语：规则生成（默认）+ AI 润色（可选）

用户问："预设比较好，还是接入一些 AI 比较好？"

### 结论：**默认用规则生成，AI 只做可选润色**

理由（逐条对应现场约束）：

| 约束 | 规则生成 | 接入 AI |
| --- | --- | --- |
| **不能出错**（听课老师在） | ✅ 确定性强，输入相同输出相同 | ❌ 可能编造（"你的证明很严谨"——可学生根本没写证明） |
| **要快**（现场 3 秒内要念出来） | ✅ 本地毫秒级 | ❌ 一次 1–5 秒，还要等网络 |
| **网络**（公开课教室网络未必可靠） | ✅ 完全离线 | ❌ 断网就卡住 |
| **隐私**（学生姓名 + 答题数据） | ✅ 不出本机 | ❌ 要发给第三方 |
| **文字自然度** | ⚠️ 模板感 | ✅ 更好 |
| **能引用具体作答** | ⚠️ 只能引用结构化数据 | ✅ 能读学生的原话 |

**关键设计**（让 AI 不越界）：**AI 只润色、不判断** ——
把规则生成的**事实**（四维得分、最弱项、与全班对比）作为**唯一上下文**交给模型，
要求"只能用给定事实改写措辞，不得新增判断"。

依据：Kluger & DeNisi (1996) 的元分析显示 **>38% 的反馈干预让表现变差**，
其中危害最大的一类是**判断错误**的反馈（把错的说成对的）；而 LLM 恰好最擅长
生成"听起来很对"的话。所以定位必须是润色器，不是评委。

### 落地形态

- **默认**：规则评语（`open_comment`，Rust + JS 双实现 + parity）
- **可选**：`AI 润色` 按钮 —— 需要用户**显式配置** API（默认无），
  请求体只含结构化事实 + 学生的**作答文本**（老师可先删改），不含姓名
- **可关闭**：设置里一键关闭，关闭后界面不出现该按钮

## 4. 教师端结构

新增子模块 `/open`（公开课），**沿用**现有领域层与 Rust 核心，只做流程编排：

```
公开课
 ├─ ① 点名     [随机抽一位]  → 大屏放大显示
 ├─ ② 抽题     [抽一道]      → 客观题优先；可限题型/标签
 ├─ ③ 答题     学生作答（客观题自动判 / 主观题老师判定三档）
 └─ ④ 评价     四维量规 + 评语 → 学生端与大屏同步显示
```

**四步是引导式的**（一步一屏），不是把现有页签堆一起 —— 公开课最怕"找不到按钮"。

## 5. 学生端与大屏

| 端 | 公开课下的行为 |
| --- | --- |
| **大屏** | 四个环节各有一屏：点名放大姓名 / 题干与选项 / 计时与作答状态 / 四维评价与评语 |
| **学生端（网页 + 安卓）** | 被点到时高亮"到你了"；答题；评价后看到自己的四维结果与评语 |

大屏沿用现有 phase 机制（新增 `open-*` 环节），学生端沿用现有快照机制。

## 6. 验收标准

- [ ] 教师端 `/open` 四步可走通，每步都有明确"下一步"
- [ ] 抽题默认客观题优先，可切"只抽客观题"
- [ ] 主观题判定三档（全对/对一半/不对）落库并影响掌握度
- [ ] 四维评价可点、可改、可跳过；权重可配置
- [ ] 评语默认规则生成（离线可用），AI 润色为可选且默认关闭
- [ ] 大屏四屏齐备；学生端被点名有提示
- [ ] e2e 覆盖：点名 → 抽题 → 答题 → 评价 全链路
- [ ] `npm run ci` 与 GitHub CI 全绿
