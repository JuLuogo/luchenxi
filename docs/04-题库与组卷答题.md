## 1. 术语与计分口径

| 术语 | 代码位置 | 说明 |
| --- | --- | --- |
| 题型 tier | `store.js:28-33` | 基础题 basic=3、拔高题 advanced=5、扩展题 extended=8、提升题 improve=10（权重可改） |
| 基准分 base | `store.js:471-475` | 题目自定义 `points` 非空时取它，否则取该题型 `weight` |
| 判定 result | `store.js:25-26` | `correct` 答对 / `half` 部分正确 / `wrong` 答错 / `skip` 跳过；非法值按 `correct` 处理（`store.js:614`） |
| 流水 record | `store.js:194-211` | 一次记分记录；**学生积分 = 所有流水 `points` 之和**（`store.js:506-519`） |
| 当前上下文 / 快捷记分 | `store.js:161`、`store.js:572-582` | `runtime.quizId` / `runtime.qid` / `runtime.sid` 只作本机记忆（`store.js:1139-1145`）；未选择试卷（`quizId` 为空）时，流水自动进入「快捷记分（课堂零散加减）」收集器 |

```
points = round2(base × ratio) + fastBonus(仅 correct 且 fast=true) - wrongPenalty(仅 wrong)
ratio ：correct=1，half=settings.halfRatio(默认 0.5)，wrong=0，skip=0        store.js:558-569
```

每条流水带 `tier` 与 `base` **快照**（`store.js:200-204`、`store.js:610-613`），因此事后改题型权重或题目分值都不改动历史分（`tests/logic.test.js:163-166`）。

## 2. 题库字段字典（`normalizeQuestion`，`store.js:175-192`）

题库为 `state.bank`（`store.js:147`）；归一化时机：加载 / 导入备份（`store.js:263`）、新增（`store.js:832-838`）、修改（`store.js:840-850`）、批量导入（`store.js:887-897`）。

| 字段 | 类型 | 默认值 / 规则（行号） | 用途 |
| --- | --- | --- | --- |
| `id` | String | `q_` + 时间36进制 + 随机串（`store.js:181`，`uid` 见 `store.js:42-44`） | 唯一标识；试卷 `questionIds` 与流水 `qid` 都引用它 |
| `tier` | String | 题型 key；不在当前 `tiers` 中则回落到第一个题型（`store.js:176-178`），兜底 `basic` | 决定默认分值与统计归类 |
| `points` | Number\|null | 空串 / null / undefined / 非数字 → `null`（`store.js:179`） | 自定义基准分；`null` 表示"继承题型权重" |
| `stem` | String | `''`（`store.js:184`） | 题干；保存时前端强制非空（`bank.js:237`） |
| `answer` | String | `''`（`store.js:185`） | 参考答案；**选择题填字母**（如 `B` / `AC`），填空题可用竖线分隔多个等价写法 |
| `options` | String[] | 非数组 → `[]`；数组逐项转字符串并**丢弃空串**（`store.js:185`） | 选择题选项，学生端由系统按顺序编号 `A/B/C…`；**非空即被判定为选择题**（§3）。编辑弹窗的多行文本框、保存时的解析、批量导入与题库导出都会带上它（`bank.js:195-197`、`bank.js:239-243`、`store.js:892`、`store.js:920`） |
| `tags` | String[] | 数组逐项转字符串；只给 `tag`（单数）则包成 `[tag]`；否则 `[]`（`store.js:186`） | 知识点标签，用于筛选与搜索；**无独立知识点表** |

| `archived` / `createdAt` | Boolean / Number | `false`（`store.js:189`）/ `Date.now()`（`store.js:190`） | 归档标记**已建模但全项目无读取点**；创建时间用于「按录入时间」排序 |

## 3. 客观题与主观题（题型按需推断）

题型**不落库**：题目对象里没有 `type` 字段，`CI.grade.typeOf`（`grade.js:22-27`）每次按下面的优先级现算，题库列表、教师端与主控台大屏都读同一份推断结果。

| 顺序 | 条件 | 题型 | 学生端表现 | 判分方 |
| --- | --- | --- | --- | --- |
| 1 | `options` 非空数组（`grade.js:24`） | `choice` 选择题 | 选项渲染为可点按钮，系统自动编号 `A/B/C…`，多选按答案字母个数自动放开（`grade.js:37-43`、`sync.js:228-242`、`student.js:254-262`） | `CI.grade.auto` 自动判分 |
| 2 | `options` 为空、`answer` 去空白后非空（`grade.js:25`） | `fill` 填空题 | 一个输入框；参考答案用竖线 / `或` / 分号分隔多个等价写法（`grade.js:73-78`、`student.js:263-265`） | `CI.grade.auto` 自动判分 |
| 3 | 两者都为空（`grade.js:26`） | `subjective` 主观题 | 多行文本框 + 提示"小组讨论后在纸上/口头作答"，可留空（`student.js:266-268`） | `auto()` 返回 `null`，**必须老师判定**（`grade.js:101`、`classroom.js:152-167`） |

- **自动判分口径**（`grade.js:98-133`）：选择题——提交字母集合与 `answer` **完全一致** → `correct`；提交是答案的**真子集**（漏选但没错选）→ `half`；含答案外的字母 → `wrong`；空提交 → `skip`（`grade.js:107-120`）。答案字母由 `parseChoice` 从任意写法中抽取（「A」「A,C」「答案：AC」等价，`grade.js:45-54`）。填空题——`normalizeText` 先做全角转半角、去全部空白与常见中英标点、忽略大小写，再与各等价写法精确比对（`grade.js:56-70`、`grade.js:122-132`），只有对 / 错，没有"部分正确"。
- **分工**：客观题（选择 / 填空）学生一提交就自动判分并立即 `recordResult({source:'student'})`（`classroom.js:169-193`）；主观题进入 `state.classroom.pending` 队列，老师点「答对/部分对/答错/跳过」时才写分（`classroom.js:200-235`）。老师也随时可在 ② / ③ 页签改判（§8）。
- **展示与辅助 API**：`typeLabel` 给中文名（`grade.js:31-34`），题库列表在题型标签后追加类型标签并标注选项个数（`bank.js:116`），教师端当前题芯片与大屏题目卡片复用同一套标签（`classroom.js:468`、`index.html:237-241`）；`canAutoGrade`（`grade.js:29`）、`optionMap`（`grade.js:37-43`）、`answerKey`（`grade.js:136-145`，公布答案时显示「B. 乙」）、`describeSubmission`（`grade.js:148-160`，教师端实时流的可读提交）。单测覆盖：`tests/logic.test.js:355-383`。

## 5. 批量导入

### 5.1 面板控件（`toggleImport`，`bank.js:276-311`）

- 默认题型 `impTier`（选项为全部题型，未显式选中 → 浏览器默认第一项基础题，`bank.js:285-287`）；文件选择 `impFile`（`accept=".json,.csv,.txt"`，`bank.js:288`）；去重开关 `impDedupe`（默认勾选「跳过题干完全相同的重复题」，`bank.js:289`）；粘贴框 `impText`（每行一题，支持「题干 竖线 答案」等写法，`bank.js:291-292`）；按钮「开始导入 / 取消 / 下载模板」与结果区 `impResult`（`bank.js:293-298`）。

### 5.2 解析规则（`parseImport`，`bank.js:314-359`）

| 输入形态 | 判定 | 结果 | 行号 |
| --- | --- | --- | --- |
| JSON 数组 `[{...}]` | 首字符 `[` 或 `{` | `JSON.parse` 后原样作为题目数组（`options` 字段随之带入） | `bank.js:317-319` |
| `{"questions":[...]}` / 单个对象 `{"stem":"..."}` / 其它 JSON | 对象且含 `questions` 数组 / 含 `stem` / 以上都不满足 | 取 `data.questions` / 包成单元素数组 / 返回 `[]` 并提示"没有解析到题目" | `bank.js:320-322`、`bank.js:373` |
| 逐行文本 | 首字符非 `[`、`{` | 按行切分、跳过空行，逐行解析 | `bank.js:324-326` |

逐行文本的分隔符**按优先级依次尝试**：

1. 竖线 `|` 或 `｜`（两侧空白自动去掉）→ `bank.js:327`
2. 制表符 `\t`（一个或多个）→ `bank.js:328`
3. 逗号 `,` / `，`：正则 `^(.+?)[,，]\s*([^,，]*)$`，**只按第一个逗号**切 → `bank.js:342-345`

**选择题写法（v3 新增）**：行内切出 ≥ 3 段、且**最后一段是纯字母（最多 2 个）**（`^[A-Ha-h][,，、\s]*[A-Ha-h]?$`，`bank.js:332`）时按选择题解析——中间各段用 `;` / `；` 拼接后再切分，并剥离行首 `A.` / `A、` / `A:` / `A)` 前缀（`bank.js:329-341`、`bank.js:333-336`），选项不足 2 个则退回普通逐行规则（`bank.js:337`）。即 `题干 | 选项1 ; 选项2 ; 选项3 | 答案字母` → `{ stem, options: ['选项1','选项2','选项3'], answer: 'C' }`；JSON 形态同理，`options` 字段原样带入：`[{ "stem": "下列哪个是质数？", "tier": "basic", "options": ["4","6","7","9"], "answer": "C" }]`。

题干取 `parts[0]`，答案取 `parts.slice(1).join(' / ')`（`bank.js:346-347`）。**中文题型前缀**：匹配 `/^(基础|拔高|扩展|提升|基础题|拔高题|扩展题|提升题)\s*[:：]\s*(.+)$/`（`bank.js:351`），补全「题」字后按 `label` 查当前题型表（`bank.js:352-356`）；**只有查得到才**剥离前缀并写入 `tier`，否则前缀原样留在题干中（`bank.js:355`）。前缀必须位于分隔符之前（属于 `parts[0]`）。

### 5.3 文件导入 vs 粘贴导入

| 维度 | 文件导入 | 粘贴导入 |
| --- | --- | --- |
| 触发与读取 | `impFile.onchange`（`bank.js:300-310`），`FileReader.readAsText(f, 'utf-8')`（`bank.js:309`） | 直接在 `impText` 输入 |
| 落点与导入 | **把文件内容写进同一个 `impText` 文本框**（`bank.js:306-307`）；两者都**不会**自动导入，仍需点「开始导入」 | 同左 |
| 解析路径 | 与粘贴完全共用 `parseImport` | 同左 |

即：文件导入只是"把文件内容灌进粘贴框"。`.csv` / `.txt` 都按同一套逐行规则解析，真正的 CSV 表头（如"题干,答案"）会被当成一道题导入。

### 5.4 默认题型、去重、模板与反馈

- **默认题型与去重**：解析结果中 `tier` 为空的项统一填 `impTier`（`doImport`，`bank.js:374`）；`opts.dedupe !== false` 且题库已存在 `q.stem === stem`（`trim` 后完全相等）时跳过（`store.js:886`），题干为空同样计入跳过（`store.js:874-875`）。
- **模板与反馈**：`downloadTemplate`（`bank.js:381-387`）为每个当前题型生成一条样例，下载 `题库导入模板.json`（结构 `{type:"ci-question-bank", version:2, questions:[...]}`）；导入后 `#impResult` 显示「导入完成：新增 **N** 题，跳过 **M** 题。」（`bank.js:376-377`），随后重渲染工具栏、列表、题型面板（`bank.js:378`）。

### 5.5 写入逻辑（`bulkImportQuestions`，`store.js:869-902`）

```
① 题干 = raw.stem || raw.question || raw.title，trim 后为空 → skipped++、丢弃     store.js:874-875
② 题型：raw.tier 命中 key → 用它；否则按 raw.tier / raw.tierLabel 匹配中文 label；
        仍无 → 取第一个题型的 key（默认 basic）                                   store.js:876-885
③ 去重：dedupe 开启且题干完全相同 → skipped++                                     store.js:886
④ normalizeQuestion 后 push 进 bank（points 空 → null；options 非数组 → []）→ log →
   commit('bank-import')                                                          store.js:887-901
```

批量导入**不会**把新知识点并入 `state.tags`（区别于 `saveEditor`），故导入的标签不出现在题库"知识点筛选"下拉中，关键字搜索仍可命中。

## 7. 组卷流程

```
① ② 组卷与答题 → ＋新建一套题（或在任意"加入"动作时由 ensureQuiz 引导命名）   quiz.js:67-72 / 162-168
② 在选题区按题型 / 关键字过滤后勾选题目（可勾「只看未加入本套题的」）           quiz.js:108-160
```

也可在题库列表点某题「加入试卷」（`bank.js:125` → `quiz.js:198-206`），或在选题区按题型点「全部加入」（`quiz.js:187-195`）。**去重**由 `addQuestionsToQuiz` 保证：已存在的 id 不追加（`store.js:1046`）；已在本套题的复选框渲染为 `disabled checked` 无法再勾（`quiz.js:131`）；重复添加时 `addToCurrent` 提示「该题已在本套试卷中」（`quiz.js:204`）。

| 函数 | 行号 | 行为与副作用 |
| --- | --- | --- |
| `createQuiz` | `store.js:988-1005` | 新建试卷（名称为空则默认「第 N 套题」，N 只数未结束且非快捷记分/历史积分的卷，`store.js:982-986`）；**立即成为当前试卷**，`currentQuizId`、`runtime.quizId` 指向它，`runtime.qid` = 第一题或 `null`；记日志「新建试卷」 |

| `setQuizQuestions` / `addQuestionsToQuiz` | `store.js:1028-1050` | 前者**整组替换**题目数组与顺序（若是当前卷且 `runtime.qid` 已不在其中，当前题重置为第一题或 `null`）；后者**追加**、已存在 id 跳过、返回新增数且**不改动 `runtime.qid`** |

| `deleteQuiz` | `store.js:1066-1075` | **物理删除整套试卷并连带其全部流水**（学生积分随之下降）；若是当前卷则清空当前试卷与当前题；**同时清理点名历史中 `quizId` 等于该卷的记录**（`store.js:1072`）；记日志「删除试卷」 |

## 8. 答题判分流程

### 8.1 老师手动判定（`judge`，`quiz.js:352-377`）

```
① 取学生：#curStudent 下拉值 → 内存 selectedStudent → runtime.sid；都无则 alert 并中止  quiz.js:355-357
② 取当前题：runtime.qid 查题库，查不到为 null（则按题型记分）                        quiz.js:359
③ 重复作答：有题且有当前卷且 answeredAlready 为真 → confirm 再记一次，取消则中止      quiz.js:360-362
④ 抢答确认：仅 result==='correct' 且 settings.fastBonus>0 → confirm 额外加分          quiz.js:363-366
⑤ 写入 recordResult({sid, qid, tier, result, quizId, source:'quiz', fast, by:'quiz'})；
   quizId 为空则记入「快捷记分」收集器                                              quiz.js:367-376 / store.js:630-631
```

判定四选一按钮 `jbtn`（`quiz.js:298-302`）带**得分预览数字**，取值 `computePoints({result, base})`：

| 按钮 | result | 预览 | 说明 |
| --- | --- | --- | --- |
| 答对 | `correct` | `+base` | 未传 `fast`，**预览不含抢答加分**，抢答在点击后二次确认（`quiz.js:364-366`） |
| 部分正确 | `half` | `+base × halfRatio` | 系数取 `settings.halfRatio`（默认 0.5） |
| 答错 / 跳过 | `wrong` / `skip` | `-wrongPenalty` / `0` | 答错默认 0 → 显示 `0`，扣分实时反映在预览中（`store.js:567`）；跳过只记流水不加分，但会占用"已答"标记 |

- **重复作答**：`answeredAlready(s, quizId, qid, sid)`（`store.js:543-547`）在**该试卷内**查找同题同人流水，不区分 `result`（跳过也算已答）；下拉框给已答学生追加「· 已答过」（`quiz.js:292-294`）。点名判分（`rollcall.js:330-348`）复用同一检查，来源记为 `rollcall`。
- **批量按题型加分**（`batchQuick`，`quiz.js:380-403`）：题型取当前题 `tier`（无当前题取第一个，`quiz.js:382-383`）→ `prompt` 输入队伍名或 `all` 表示全班（`quiz.js:385-388`）→ 队伍名**精确匹配**，找不到 `alert('未找到队伍：X')`（`quiz.js:390-392`）→ 名单 `studentsOf`（`store.js:528-531`，不过滤停用学生）→ `confirm`（`quiz.js:396`）→ 逐个 `recordResult({result:'correct', source:'quiz', by:'quiz-batch'})`（`quiz.js:397-402`）。

### 8.2 学生端提交（`classroom.js`，v3 新增的第 3 条记分入口）
学生端把作答打包成命令 `{kind:'answer', teamId, sid, qid, choice|text|skip}` 经枢纽转发给教师端（`student.js:476-502`、`sync.js:140-147`），教师端 `CI.classroom.handleCmd` 接手（`classroom.js:110-196`）：

```
① 定人：命令 sid → 当前学生（须同队）→ 该队第一个成员；都没有则只写一条失败实时流   classroom.js:56-65 / 130-136
② 去重：**有当前题且有当前试卷**且 answeredAlready 为真 → 只推「重复提交，已忽略」并返回 {ok:false,reason:'duplicate'}（不写分、不改判定）  classroom.js:138-145
③ 判分：CI.grade.auto(q, {choice,text,skip})                                    classroom.js:148-150
     返回对象（选择 / 填空）→ 立即 recordResult({source:'student', by:'student', note:提交描述}) 并补一条带分的实时流  classroom.js:169-193
     返回 null（主观题）→ push 进 state.classroom.pending（上限 60），等老师点按钮    classroom.js:98-105 / 151-166
④ 待办判定：resolvePending(id, result) → recordResult({source:'student', by:'classroom-confirm'})；「丢弃」只移除不记分  classroom.js:200-246
```

| 记分入口 | 触发者 | `recordResult` 的 `source` / `by` | 依据 |
| --- | --- | --- | --- |
| 老师手动判定（② 页签） | 老师点四选一 | `quiz` / `quiz` | `quiz.js:367-376` |
| 老师点名判分（③ 页签） | 老师点四选一 | `rollcall` / `rollcall` | `rollcall.js:338-346` |
| **学生端提交**（⑦ 页签链路） | 学生端命令 / 老师确认待办 | `student` / `student`（自动判分）或 `student` / `classroom-confirm`（主观题判定） | `classroom.js:169-178`、`classroom.js:210-219` |

- **与"重复作答"的关系**：三条入口共用去重判定。学生端是**静默忽略**（不弹确认，`classroom.js:138-146`）；老师和点名路径是二次 `confirm` 后可以再记一次（`quiz.js:360-362`、`rollcall.js:335-337`）。学生端去重规则（`classroom.js:138-141`）：**有当前试卷**时按该卷判重（`answeredAlready`）；**未选择当前试卷**（记入"快捷记分"）时按该题的历史流水判重 —— 两种情况都不会重复加分。
- **抢答**：`{kind:'buzz'}` 进 `state.classroom.buzz`，**同队同题去重**（`classroom.js:77-96`，重复时只写日志「（重复，已忽略）」）；抢答本身不记分，只是排队与展示（`classroom.js:305-313` 可「设为当前学生」再走点名判分）。三类队列都有上限：`feed` 60 / `pending` 60 / `buzz` 40，超出从尾部丢弃（`classroom.js:74`、`classroom.js:102`、`classroom.js:89`）。单测覆盖：`tests/logic.test.js:384-487`（自动加分、重复提交被忽略、主观题待确认与判定）。

## 9. 数据结构示例

### 9.1 一套试卷（`state.quizzes[i]`，结构见 `store.js:265-275`）

```json
{
  "id": "qz_lx9f3ka2b",
  "name": "第 1 套题 · 2026/9/30",
  "note": "函数与导数随堂测",
  "createdAt": 1759240800000,
  "closedAt": 0,
  "questionIds": ["q_lx9f1a", "q_lx9f2b", "q_lx9f3c"],
  "records": [
    { "id": "rc_lx9g7hd", "sid": "st_lx8k2p", "qid": "q_lx9f1a",
      "tier": "basic", "quizId": "qz_lx9f3ka2b", "result": "correct",
      "base": 3, "ratio": 1, "points": 3,
      "source": "student", "note": "B. 乙", "at": 1759241012345, "by": "student" }
  ]
}
```

`closedAt: 0` 表示未结束，结束后为结束时间戳（`store.js:1054`）；`questionIds` 的数组顺序就是答题顺序。「本套题积分流水」面板按 `at` 倒序只显示**最近 100 条**（`quiz.js:415`），更多时提示改用「导出本套流水」——后者走 `analysis.questionCSV`，列为时间 / 试卷 / 学生 / 队伍 / 题型 / 题目 / 判定 / 基准分 / 得分 / 计分方式（`quiz.js:97-102`、`analysis.js:402-419`）。

### 9.2 一条流水（`record`，字段定义 `store.js:194-211`）

上例 `records[0]` 即一条完整流水：`id` / `at` 为流水 id（`rc_` 前缀，`store.js:197`）与时间戳（`store.js:208`）；`sid`、`qid`、`quizId` 分别指向学生、题目、试卷，快捷加分与手动调整 / 归零的 `qid`、`quizId` 均为 `null`（`store.js:198-201`）；`tier` 与 `base` 是**记分时的快照**（手动类 `tier` 为空串，`store.js:200`、`store.js:203`）；`result` 可为 `correct`/`half`/`wrong`/`skip`/`manual`（`store.js:195`、`store.js:202`）；`ratio` 记录当次系数，`half` 记的是 `halfRatio` 快照（`store.js:622`）；`points` 为实际记入积分、可为负（`store.js:205`）；`source` 为 `quiz`/`quick`/`rollcall`/`student`/`manual`/`reset`（`store.js:206`、`classroom.js:176`、`classroom.js:218`）；`by` 为操作页签 `quiz`/`quiz-batch`/`rollcall`/`class`/`manual`/`student`/`classroom-confirm`（`store.js:209`、`quiz.js:375`、`quiz.js:400`、`classroom.js:178`、`classroom.js:221`）；`note` 默认空，学生端提交写入可读答案描述、归零流水为「归零抵冲」（`classroom.js:177`、`store.js:665`）。

## 11. 已知限制

| # | 限制 | 代码依据 |
| --- | --- | --- |
| 1 | **试卷题目顺序就是答题顺序**，无独立排序字段，上移 / 下移直接改 `questionIds`；三种排序都不支持拖拽 | `store.js:1028-1038`、`quiz.js:252-261`、`bank.js:31-38` |
| 2 | 知识点只是 `tags` 字符串数组，**无独立知识点表**；筛选为精确匹配，且 `state.tags` 仅由编辑弹窗追加，批量导入的标签不进下拉 | `store.js:186`、`bank.js:24`、`bank.js:266-268` |
| 3 | 「（题目已从题库删除）」占位（`quiz.js:223-225`）在正常删除流程下**不会**出现（`removeQuestion` 会同步清理各试卷引用）；它只在题库与试卷引用不一致时出现，例如导入的外部备份 `questionIds` 指向了不存在的题目，需手动移除 | `store.js:857-859`、`store.js:272`、`quiz.js:222-226` |
| 4 | 批量加分的确认文案用**题型权重**，实际记分按题目基准分（`questionPoints`），题目设了自定义分值时文案与结果不符；且逐人 `commit`（N 人 → N 条日志与 N 次 `change` 事件，非单事务）、目标队伍按**名称精确匹配**、名单取 `studentsOf` **不排除 `active === false` 的停用学生** | `quiz.js:385-402`、`store.js:635`、`store.js:528-531`、`store.js:611-613` |
| 5 | 逐行文本导入的逗号分隔**只认第一个逗号**，题干含中文逗号会被误切，宜改用竖线或 Tab；**选择题写法只认 1~2 个答案字母**（正则 `^[A-Ha-h][,，、\s]*[A-Ha-h]?$`，`bank.js:332`），三选及以上的答案（如 `ABC`）不会被识别为选择题、会被整行当作"题干 竖线 答案"导入；JSON 解析失败直接 `alert`，已输入内容不保留；去重是"`trim` 后题干完全相同"，不做全半角 / 空白归一化 | `bank.js:332`、`bank.js:342-345`、`bank.js:367-372`、`store.js:886` |
| 6 | 题库导出不含 `id` / `createdAt` / `archived`，回导后生成新 id，老流水无法再指向新题；题型匹配失败会落到第一个题型；`archived`（归档）虽已建模，但全项目无任何读写入口 | `store.js:913-925`、`store.js:876-885`、`store.js:189` |
| 7 | 「快捷记分」收集器按**名称**查找，同名的「快捷记分（课堂零散加减）」试卷会被复用；一套题的流水面板只渲染最近 100 条（数据不丢，完整内容需导出 CSV） | `store.js:572-582`、`quiz.js:415` |
| 8 | **题型靠推断、不落库**：没有 `type` 字段，`options` 一被清空就会退回填空题或主观题（`store.js:185`、`grade.js:22-27`）；选择题只比较字母集合，多选漏选一律按 `settings.halfRatio`，没有按漏选个数递进的部分分（`grade.js:112-114`）；填空题只做字符级归一化，不做单位换算、同义改写或数值等价（`grade.js:56-70`） | `grade.js:22-27`、`grade.js:107-132` |
| 9 | **选择题校验只在编辑弹窗做**：答案字母必须落在选项范围内、至少 2 个选项（`bank.js:244-252`），但批量导入 / JSON 直接写入的题目不做这项校验，字母超范围时该题永远判不对；主观题（以及没填 `answer` 的题）`auto()` 恒返回 `null`，**学生提交后必须老师点一次按钮才写分**，且学生端同一题**重复提交会被静默忽略**（不覆盖首次判定），老师要改判只能在 ② / ③ 页签补记或撤销流水 | `bank.js:244-252`、`store.js:892`、`grade.js:101`、`classroom.js:138-145` |
| 10 | 学生端的抢答榜与待确认队列**都有上限**（`buzz` 40 条 / `pending` 60 条，超出从尾部丢弃），一节课长期不处理时旧提交会被挤掉、不留历史 | `classroom.js:89`、`classroom.js:102` |
