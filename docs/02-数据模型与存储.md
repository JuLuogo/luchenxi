# 02 · 数据模型与存储

> 唯一数据源是 `assets/js/store.js`（v3 的 `classroom.js` / `sync.js` 只通过 `CI.store.tx` 写它）。本文是字段字典与持久化说明；计分公式见 [03](03-加权积分规则.md)，WS 结构见 [07](07-通信协议与API.md)，多端数据流见 [10](10-多端协同架构.md)。

## 2. 顶层结构

```jsonc
{
  "version": 2,
  "rev": 37,                 // 单调递增版本号：每次 commit 自增，用于缓存失效与调试
  "updatedAt": 1790778815841,
  "settings": { ... },       // 全局设置（见 §4）
  "tiers":   [ ... ],        // 题型与权重（见 §5）
  "tags":    ["函数与导数"],  // 知识点候选（题库编辑时的 datalist）
  "teams":   [ ... ],        // 队伍（分组视图，见 §6）
  "students":[ ... ],        // 学生（计分主体，见 §7）
  "bank":    [ ... ],        // 题库（见 §8 与 [04]）
  "quizzes": [ ... ],        // 试卷 + 积分流水（见 §9 与 [04]）
  "currentQuizId": "qz_x",   // 当前试卷（持久化，刷新后仍生效）
  "rollcall": { ... },       // 点名状态（见 §10 与 [06]）
  "classroom": {             // v3 课堂协同分区（随课堂数据持久化，见 §15）
    "pending": [ ... ],      //   待老师判定的主观题提交（上限 60）
    "buzz":    [ ... ],      //   抢答榜（上限 40）
    "feed":    [ ... ]       //   课堂实时流（上限 60）
  },
  "logs":    [ ... ],        // 操作日志（最多 800 条，见 §11）
  "runtime": {               // 运行时上下文（本地记忆，随状态一起持久化）
    "quizId": "qz_x",        //   当前试卷
    "qid":    "q_y",         //   当前题
    "sid":    "st_z",        //   当前学生（点名命中的学生）
    "accepting": true,       //   v3：是否接收学生作答（见下）
    "reveal":    false       //   v3：是否向大屏/学生端公布答案
  }
}
```

顶层对象的构造与缺省值在 `store.js:125` `defaultState()`；任何外部数据（localStorage、导入的备份）都会先过 `store.js:214` `normalize()` 补齐字段，因此**缺字段不会报错**（`runtime` 是与缺省值合并，`store.js:224`）。

v3 新增的两个运行时开关（`defaultState()` 里没有它们，只有课堂协同页点过按钮才会写入）：

| 字段 | 含义 | 谁写 | 界面上在哪控制 |
| --- | --- | --- | --- |
| `runtime.accepting` | 是否接收学生作答：为假时学生端的「提交答案 / 抢答」按钮禁用（`student.js:293`） | `setAccepting`（`classroom.js:256`）走 `store.tx` | 页签⑦「课堂协同」→「作答控制」按钮（`admin.html:152`，渲染 `classroom.js:441`，点击 `classroom.js:543`） |
| `runtime.reveal` | 是否公布答案：为假时快照里的 `answerKey` 是 `null`（`sync.js:243`），大屏与学生端都看不到答案 | `setReveal`（`classroom.js:263`）走 `store.tx` | 页签⑦「作答控制」的「公布答案 / 隐藏答案」（`classroom.js:467`、`classroom.js:562`） |
| `runtime.revealedQid` **（v3）** | 记住"公布的是哪一道题"：判定口径是 `reveal && revealedQid === 当前题 id`（`classroom.js:273` `isRevealed`），所以**换题后答案自动收起**，不会把下一题的答案泄露给学生端与大屏 | `setReveal(true)` 写入 `runtime.qid`，`setReveal(false)` 与 `moveQuestion` 清空 | 同上；换题入口是页签⑦的「← 上一题 / 下一题 →」（`classroom.js:284` `moveQuestion`，快照里的进度见 `sync.js:273` `questionIndex`） |

`classroom` 是 v3 新增的顶层分区（细节见 §15）：`normalize()` 不认识它但**不会删掉**（只补齐自己认识的分区，`store.js:214`–`store.js:288`），`importAll`（`store.js:1188`）因此也会原样保留；只有 `factoryReset`（`store.js:1162`）会连 `accepting`/`reveal` 一起丢弃（重建 `defaultState()` 时只保留 `teams/students/bank/tiers/tags/settings`，`store.js:1164`–`store.js:1167`）。

## 3. 写操作规范

```js
CI.store.tx(reason, function (state) { /* 直接改 state */ return result; }, {
  type: '日志标题',                       // 省略则不打日志
  detail: '文本' | function (state, result) { return '文本'; }
});
```

`tx` 的实现见 `store.js:431`，它保证：

1. 先执行 `mutator(state)`，再写日志，最后 `commit`；
2. `commit`（`store.js:416`）→ `rev++`、`updatedAt = Date.now()`、写 localStorage、派发 `change` 事件；
3. 所有对外写操作（加学生、改权重、记分、点名…）都走这条路径，因此**没有"绕过日志的修改"**。

读取统一用选择器：`scoreOf` / `teamScore` / `studentsOf` / `recordsOf` / `question` / `quiz` / `student` / `team` / `tierOf` / `questionPoints`（`store.js:447`–`store.js:543`）。选择器同时支持 `selector(state, id)` 与 `selector(id)`（用当前状态）两种写法，见 `store.js:460` `pick2`。

  "desc": "课本概念与常规运算，面向全体" }

| --- | --- | --- | --- | --- |

## 6. teams（队伍）

```jsonc
{ "id": "tm_xxx", "name": "红队", "icon": "🔴", "color": "#e74c3c", "order": 0 }
```

- 队伍**不存分数**：`teamScore = Σ 成员 scoreOf()`（`store.js:521`），因此不存在分数不一致。
- `removeTeam`（`store.js:753`）会把该队学生转入剩余的第一支队伍，并重排 `order`；至少保留一支队伍由 UI 层把关（`admin.js:121`）。
- 学生 `teamId` 在 `normalize()` 中校验，指向不存在的队伍时回落到第一支队伍。

## 7. students（学生，计分主体）

```jsonc
{ "id": "st_xxx", "name": "张三", "teamId": "tm_xxx", "active": true, "joinedAt": 1790000000000 }
```

| 字段 | 说明 |
| --- | --- |
| `name` | 显示名，可直接在卡片上改名（`updateStudent`） |
| `teamId` | 所属队伍，用于分组榜、点名范围、队伍分聚合 |
| `active` | `false` 表示不参与点名（保留在名单与统计中） |
| `joinedAt` | 录入时间 |

> **注意：学生对象里没有 `score` 字段。** 分数一律通过 `CI.store.scoreOf(state, sid)` 由流水实时求和（带 `rev` 级缓存，`store.js:506`）。这样"归零""撤销""删试卷"都不需要额外同步分数。

批量录入：`addStudentsBulk(text, teamId)`（`store.js:787`）按 `空格 / 逗号 / 顿号 / 分号 / 换行 / 制表符` 切分姓名。

## 8. bank（题库）

字段字典、导入导出格式与界面能力详见 [04 题库与组卷答题](04-题库与组卷答题.md)。归一化函数：`store.js:175` `normalizeQuestion`。

v3 的题目对象多一个字段 `options: string[]`（选择题选项文本，展示时按 `CI.grade.LETTERS`（`grade.js:20`）自动编号 A/B/C…）：`[]` 表示非选择题；它与 `answer` 在**同一行**归一化（`store.js:185`，去掉空串），`bulkImportQuestions`（`store.js:892`）与 `exportBank`（`store.js:920`）都支持，编辑器里「题目类型」选选择题才显示选项框（`bank.js:195`、`bank.js:239`）。

**题型不落库，按需推断**（`grade.js:22` `typeOf`）：`options` 非空 → `choice` 选择题；否则 `answer` 非空 → `fill` 填空题；否则 → `subjective` 主观题（`auto()` 返回 `null`，必须老师判定，`grade.js:98`）。判分规则见 [10 多端协同架构](10-多端协同架构.md)。

### 9.1 积分流水 record（全系统最重要的一张表）

```jsonc
{
  "id": "rc_xxx",
  "sid": "st_张三",     // 谁
  "qid": "q_a",         // 哪道题（手动分/快捷加分为 null）
  "tier": "basic",      // 计分时的题型快照（手动分/归零为 ""）
  "quizId": "qz_xxx",   // 归属试卷（可空：进入"快捷记分"收集器）
  "result": "correct",  // correct | half | wrong | skip | manual
  "base": 3,            // 计分基准分（题型权重或题目自定义分值）
  "ratio": 1,           // 生效系数（half 时为 halfRatio）
  "points": 3,          // 实际计入积分（可为负）
  "source": "quiz",     // quiz | quick | rollcall | manual | reset | student
  "note": "",           // 备注
  "at": 1790000000000,  // 时间戳
  "by": "quiz"          // 操作来源页签，便于排查
}
```

定义与默认值：`store.js:194` `normalizeRecord`（第 206 行的代码注释仍只列了前四种 `source`，`student` 是 v3 新增的实际取值）。

`source` 取值表：

| `source` | 写入者 | 典型场景 |
| --- | --- | --- |
| `quiz` | 组卷答题页 | `quiz.js:352` `judge`、`quiz.js:380` `batchQuick` |
| `quick` | 卡片 / 点名页的题型按钮 | `admin.js:329`、`rollcall.js:351` |
| `rollcall` | 点名后判定 | `rollcall.js:330` |
| `manual` / `reset` | 手动 ±分 / 归零抵冲 | `store.js:640`、`store.js:656` |
| `student` **（v3）** | **学生端提交**：客观题自动判分（`classroom.js:178`，`by:'student'`）；主观题老师判定后（`classroom.js:219`，`by:'classroom-confirm'`） | 见 §15 与 [03 §6](03-加权积分规则.md) |

**三类特殊流水**

| 类型 | 特征 | 作用 |
| --- | --- | --- |
| 手动调整 | `result:'manual'`、`tier:''` | 卡片 ±1/±2/自定义分（`store.js:640` `addManual`） |
| 归零抵冲 | `source:'reset'`、`points = -当前分` | 保留历史的前提下把分数清零（`store.js:656`） |
| 快捷加分 | `source:'quick'`、`qid:null`、带 `tier` | 卡片上的题型按钮，计入该题型统计（可开关） |

**收集器试卷**：未选择试卷时产生的流水统一进入名为「快捷记分（课堂零散加减）」的试卷，避免污染正式试卷（`store.js:572` `collectorQuiz`）。它不出现在试卷下拉框中（`quiz.js:22` `quizList` 过滤），也会被「清空全部积分」一起清空。

## 12. v1 → v2 迁移

触发条件：localStorage 没有 `ci_data_v2`，但存在 v1 的 `teams` 数组（`store.js:368` `load()`）。

迁移逻辑（`store.js:296` `migrateFromV1`）：

1. 每个 v1 队伍 → 一个 v2 队伍（保留 `name`/`icon`，补充 `id`/`color`/`order`）；
2. 为每个 v1 队伍创建一个**同名"队伍代表"学生**，把 v1 的 `score` 写成一条 `manual` 流水挂在他名下 —— 这样历史分数不会凭空消失（老师可改名或删除该学生）；
3. v1 的 `opLogs` 取最近 200 条并入 `logs`，并追加一条「数据迁移」日志；
4. 迁移结果立即写入 `ci_data_v2`，之后不再读 v1 键。

> 迁移后「队伍榜」分数与 v1 一致（因为队伍分 = 唯一成员分）；老师需要把"队伍代表"学生改名为真实学生，或删除后重新导入名单。

## 14. 容量与清理

- localStorage 单域约 5MB；`save()`（`store.js:353`）写入失败时会把 `logs` 裁剪到 100 条后重试一次。
- 真正吃容量的是积分流水（每条约 250 字节）：1 万条 ≈ 2.5MB。建议每学期归档一次：
  1. 页签⑥「导出全部数据（备份）」；
  2. 「清空全部积分」或删除旧试卷（会连带删除其流水）；
  3. 需要历史时用导出的 JSON 留档。
- 「恢复初始状态」= `factoryReset`（`store.js:1162`）：清空试卷、流水、点名历史，**保留**名单、题库、题型与设置；`state.classroom` 与 `runtime.accepting/reveal` 会被一起重置（保留清单见 `store.js:1164`–`store.js:1167`）。

## 15. classroom（v3 课堂协同分区）

学生端只发命令、不持有数据；教师端 `CI.classroom` 处理后把课堂过程数据写进 `state.classroom`（`classroom.js:31` `box()` 负责补齐缺失分区并按需建对象）：

| 分区 | 条目字段 | 上限 | 谁写 |
| --- | --- | --- | --- |
| `pending` | `{id:'pd_x', at, sid, teamId, qid, quizId, answer, auto:false, backlog}`（`classroom.js:100`） | 60（`classroom.js:102`） | 主观题提交入队（`classroom.js:153`）；老师判定（`classroom.js:208` `splice`）或丢弃（`classroom.js:241`）后出队 |
| `buzz` | `{id:'bz_x', at, teamId, qid, sid, by}`（`classroom.js:84`） | 40（`classroom.js:89`） | 学生抢答（`classroom.js:78`，同队同题去重，`classroom.js:82`） |
| `feed` | `{id:'fd_x', at, kind, teamId, sid, qid, result, answer, expected, auto, points, text}`（`classroom.js:73`） | 60（`classroom.js:74`） | 入座/抢答/提交/判定/丢弃/系统提示，一律 `unshift`（新的在前） |

- 三个分区都在 `ci_data_v2` 里，**随课堂数据一起持久化**（也随 `dump` 通道进枢纽），教师端刷新或换设备后待确认提交不丢；
- 上限在写入后按长度截断；清空入口是页签⑦的「清空抢答榜」（`classroom.js:248`）与「清空实时流与待确认」（`classroom.js:252`，会同时清 `feed`/`pending`/`buzz`）；
- `resetAllScores`（`store.js:1147`）只清流水与点名历史，**不动** `classroom`（即"全班归零"不会清掉待确认提交）；`factoryReset` 才会一并丢弃。
- 主观题在老师判定前**不产生任何流水**，所以待确认条目不是积分，也不进统计（`classroom.js:152`–`classroom.js:166`）。

## 16. 多端协同的数据落点（学生端 / 教师端 / 枢纽）

| 端 | 角色 | 持有课堂数据？ | 落点 |
| --- | --- | --- | --- |
| 教师端 `admin.html` | `host` | ✅ **唯一权威** | 全部业务数据写 `ci_data_v2`（`store.js:19`）；判定统一走 `recordResult`（`classroom.js:169`、`classroom.js:210`） |
| 大屏 `index.html` | `stage` | ❌ 只读 | 只消费快照（`sync.js:216` `snapshot()`），不修改任何数据 |
| 学生端 `student.html` | `team` | ❌ **不持有** | 内存里只有最近一次快照（`student.js:35`）+ 三个本地键 `ci_team`/`ci_room`/`ci_answerer`（`student.js:14`–`student.js:16`）；只上行 `{type:'cmd'}`（`student.js:498`） |
| 枢纽 `sync-server.js` | 转发 + 缓存 | 缓存快照与完整数据 | 内存房间对象（`sync-server.js:72`），落盘 `rooms/<房间>.json`（`sync-server.js:65`、`sync-server.js:96`）；`dump` 通道只有教师端可读写（`sync-server.js:215`、`sync-server.js:223`） |

数据方向：教师端 `store` 变更 → `sync.push()`（`sync.js:351`，400ms 合并）→ 枢纽广播 `state`；学生命令 `cmd` → 枢纽转给 `host`（教师端离线则排队，`sync-server.js:173`）→ `CI.classroom.handleCmd`（`classroom.js:110`）→ 写 `classroom` 分区 + `recordResult({source:'student'})` → 再次 `push` 回学生端与大屏。学生端与枢纽都**不写** `ci_data_v2`，因此成绩永远只有一个真相来源；架构、房间、容错与安全边界见 [10 多端协同架构](10-多端协同架构.md)。
