# 01 · 项目现状与架构（v3）

> 面向接手开发的工程师：先读这一篇，再按需读 [02 数据模型](02-数据模型与存储.md) 与各功能篇。

## 1. 一句话定位

一套**零构建、纯静态**的课堂积分系统：老师用教师端 `admin.html` 记分/组卷/点名/课堂协同，教室大屏 `index.html` 实时显示榜单与当前题，学生用手机打开学生端 `student.html` 按小组入座答题与抢答；三端由跑在**教师机本地的枢纽** `sync-server.js` 用「房间 + 角色」连起来（不需要公网服务器）。数据存在浏览器 `localStorage`（教师端是唯一写入者），无需数据库与账号体系。

## 2. v1 → v2 → v3 的变化总览

| 维度 | v1（重构前） | v2 |
| --- | --- | --- |
| 计分主体 | 队伍（`teams[{name,score}]`） | **学生**（`students`），队伍只是分组视图 |
| 加分方式 | 固定按钮 +1 / +3 / -1 / -2 | **按题型加权**（基础 3 / 拔高 5 / 扩展 8 / 提升 10，可改）+ 自定义分值 |
| 积分存储 | 直接存数字，改了就没了 | **流水派生**：积分 = 流水 `points` 之和，可撤销、可追溯 |
| 题库 | 无 | 题库 CRUD、题型/知识点/分值、批量导入、JSON 导出 |
| 组卷答题 | 无 | 一套题 = 若干题 + 流水，支持判定记分与流水导出 |
| 学情分析 | 无 | 按题型/知识点统计、薄弱识别、文字总结、CSV 导出 |
| 点名 | 无 | 三种模式、轮次池、防连点、点完即判分 |
| 代码组织 | 单文件 `admin.html`（1090 行，内联 CSS/JS） | 页面骨架 + `assets/css` + `assets/js` 8 个模块 |
| WebSocket | 仅中继 | 中继 + 快照落盘 + 心跳 + **同端口静态托管** |
| 大屏 | 只有队伍榜 | 队伍榜 + 个人榜 + 当前题 + 最近得分滚动条 |

## 4. 运行时架构

```
┌────────────────────────────────┐      ┌────────────────────────────────┐
│  admin.html（教师端 role=host） │      │  index.html（大屏 role=stage）  │
│  ────────────────────────────  │      │  ────────────────────────────  │
│  store.js ← 唯一数据源/唯一写者  │      │  只消费快照，不产生数据          │
│    ↓ change 事件                │      │  队伍榜 / 个人榜 / 当前题        │
│  admin.js 重渲染（30ms 防抖）    │      │  （选项 + 公布答案）/ 抢答榜 /    │
│  classroom.js 处理学生命令、判分 │      │  最近得分；状态栏显示在线组数     │
│  sync.js 节流推送（400ms）+ dump │      │  收到 state / presence 即渲染    │
└──────┬─────────────────────────┘      └───────────────▲────────────────┘
       │ 上行 {type:'state',payload} 全量快照（房间内广播） │
       │ 下行 {type:'cmd',cmd} 学生命令（枢纽转发）        │
       ▼                                                │
  ┌──────────────────────────────────────────────────────────────┐
  │  sync-server.js —— 教师机「本地枢纽」（房间隔离，无业务逻辑）  │
  │  · HTTP：/ 教师端 · /join 学生端 · /stage 大屏 · /qr.png · /health│
  │  · WS  ：角色 host / stage / team；缓存每房间最新快照，新连接即补发│
  │  · 落盘：rooms/<房间>.json（800ms 防抖），枢纽重启/换设备即恢复  │
  │  · 转发：cmd → host；host 离线时排队（≤60 条），上线用 cmd-backlog 补发│
  │  · dump：完整课堂数据单独通道，仅 host 可读写、永不广播          │
  │  · presence：谁在线、哪支队伍已入座；30s ping/pong 清理假连接    │
  └──────────────────────────────────────────────────────────────┘
       ▲
       │ {type:'cmd'}：入座 hello / 抢答 buzz / 作答 answer
┌──────┴─────────────────────────┐
│  student.html（学生端 role=team）│
│  无状态：只渲染广播来的快照；      │
│  入座 / 答题 / 抢答 / 本组 / 我的；│
│  ?view=board = 小组公屏          │
└────────────────────────────────┘
```

要点：

- **单写者模型**：只有教师端（`role=host`）产生数据；大屏与学生端只读渲染。学生端的入座/抢答/作答以 `{type:'cmd'}` 上行，由教师端 `CI.classroom.handleCmd`（`classroom.js:110`）判定并落库。多台教师端同时打开时，后写者覆盖 `localStorage` 与枢纽快照（不冲突合并），详见 [07 通信协议](07-通信协议与API.md) 的「已知限制」。
- **数据流向**：`store.commit()` → `change` 事件 → ① 界面重渲染 ② `sync.push()`（400ms 节流，`sync.js:351`）→ 枢纽缓存并广播 → 大屏 / 学生端；完整课堂数据另走 `dump` 通道（`sync.js:325`），只在教师端与枢纽之间往返，学生端永远拿不到。
- **离线可用**：WebSocket 断开时教师端功能完全可用（`scheduleReconnect` 指数退避重连，`sync.js:150` 提示「单机模式仍可继续记分」），只是学生端接不进来（课堂协同页显示「未连接枢纽（单机模式…）」，`classroom.js:379`）；大屏显示「连接断开，重试中…」，学生端显示「已断开，重连中…」。

## 7. 关键设计决策

1. **积分由流水派生**（`store.js:506` `scoreOf`）：不存冗余分数，撤销/删除/归零都只是增删流水，天然一致；代价是每次渲染要遍历流水（课堂规模下可忽略，并按 `rev` 做了缓存）。
2. **计分快照**：流水写入时记录 `tier` 与 `base`（`store.js:194` `normalizeRecord`），事后改题型权重或题目分值**不会**改写历史成绩。
3. **学生为主体、队伍为视图**：队伍分实时由成员分求和（`store.js:521` `teamScore`），避免两套分数打架。
4. **统一写入口 `tx(reason, mutator, opts)`**（`store.js:431`）：自动写日志 + `commit`（`rev++` → 落盘 → 广播 `change`），保证「任何改动都可追溯」。
5. **零构建、经典脚本**：不用 ES Module，保证双击 `file://` 打开也能跑；也因此能用 `<script src>` 拆分文件而不需要打包器。
6. **大屏兼容旧协议**：`payload.teams` 结构保留（新增 `students`/`meta`），老版 `index.html` 仍能渲染；枢纽仍接受 `{type:'leaderboard'}` 裸推送（`sync-server.js:188`）。
7. **教师端仍是唯一写入者**：学生端没有 `store`，只发 `{type:'cmd'}`；判定、加分、落库全部发生在教师端（`classroom.js:110` `handleCmd` → `store.recordResult`），避免"谁的分数才算数"的歧义，也让学情口径天然统一。
8. **枢纽只缓存与转发**：`sync-server.js` 不做任何业务计算，只按房间保存最新快照、转发命令、维护在线状态（`sync-server.js:198-245`）；完整课堂数据走独立的 `dump` 通道（`sync-server.js:215-228`，仅 host 可读写、永不广播），学生端拿不到无关的大数据。换掉枢纽实现不影响教师端逻辑。
9. **学生端无状态**：学生端只渲染最近一次广播的快照（`student.js:35`），本地只记「我是哪组 / 我是谁」（`student.js:14-16`），刷新后重新入座即可；降低移动端兼容与存储成本（不用 IndexedDB，也不存课堂数据）。
10. **单机模式兼容**：没连上枢纽时教师端退化为 v2 的单机形态（记分/点名/组卷/学情全部照常，`sync.js:150`、`classroom.js:379` 给出提示），只有学生端与大屏不可用；老师不需要为了"能用"先折腾网络。

## 8. 现状盘点（已知技术债）

| 项 | 说明 | 影响 |
| --- | --- | --- |
| 单写者假设 | 多台教师端同时改仍会互相覆盖，**没有冲突合并**；`host` 也没有独占锁，两台教师端可同时连进同一房间 | 多老师同改需人工约定「只有一台开教师端」 |
| 房间里没有鉴权 | 知道地址的人都能以 `host` / `stage` / `team` 连进同一房间（房间号只是隔离，不是密码） | 适合可信的教室局域网；公网部署需自行加鉴权或反代（见 [07 通信协议](07-通信协议与API.md)） |
| 学生端离线不排队 | 学生端断网时命令直接提示失败（`student.js:114`），不会缓存在本地等重连；**只有「教师端离线」由枢纽排队**（≤60 条，`sync-server.js:240-242`） | 网络抖动期间的作答会丢，需要学生重新提交 |
| localStorage 容量 | 约 5MB；超出配额时 `save()` 只裁剪**日志**（保留最近 100 条）后重试（`store.js:353-365`），积分流水不会被裁剪，写不下就是落盘失败 | 长期使用建议定期「导出全部数据」并归档 |
| 房间存档无清理策略 | `rooms/<房间>.json` 只增不减，切换房间也不会删除旧存档 | 长时间多房间使用会累积；可手动删除文件 |
| 数据在浏览器 | 换设备/清缓存即丢失 | 教师端可从枢纽 `dump` 通道恢复；仍建议每节课后导出备份 |
| v1 计时器样式 | 原 `admin.html` 中的 `.timers-*` / `.segments-*` 只有样式没有界面，v2 已移除 | 如需分段计时需重新实现（见 [09 路线图](09-路线图与变更记录.md)） |
| 同步粒度 | 每次变更全量推送榜单快照（学生端只拿 `students[]` 轻量统计） | 课堂规模无压力；数据量大时可改为增量 |
| 无自动化跨浏览器测试 | 仅 Chrome/Edge 无头验证（教师端 e2e 52 项 + 多端 e2e 用例） | Safari/老 iPad 需人工验证一次（学生端尤其要试） |
