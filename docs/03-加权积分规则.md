# 03 · 加权积分规则

> 计分引擎全部在 `assets/js/store.js`（纯逻辑、不碰 DOM，可在 Node 中直接跑），统计侧口径在 `assets/js/analysis.js`；v3 的客观题自动判分（`assets/js/grade.js`）只负责判出 `result`，加分仍回到 store 的同一套公式。本文只写**代码的真实行为**，每个结论都能按行号回查。
>
> **引用约定**：行号写成 `assets/js/store.js:558`（与其它篇的简写 `store.js:558` 指同一文件）；**统一术语**：题型 `tier` / 权重 `weight` / 基准分 `base` / 判定 `result` / 流水 `record` / 快捷记分 / 加权得分率 `creditRate`。

## 1. 设计目标：为什么不再用「手动 +1/+3」

v1 只有队伍和一个数字分，加分靠固定按钮，分不出「这 3 分是基础题还是压轴题」；v2 把计分主体换成学生，加分改为**按题型加权 + 逐条流水**（对照见 [01 §2](01-项目现状与架构.md)）：

| 目标 | 代码落点 |
| --- | --- |
| 分数与题目难度挂钩，而非老师临时拍 | 题型四档权重（`assets/js/store.js:28`）+ 题目自定义分值（`assets/js/store.js:471`） |
| 每一分都能说清来源、可撤销 | 积分不落库，由流水求和派生（`assets/js/store.js:506`） |
| 判定口径可调（部分、扣分、抢答） | `settings` 计分参数（`assets/js/store.js:131`） |

| 术语 | 含义 | 代码 |

## 4. 计分公式

**基准分**：base = 题目 `points`（非空）否则题型 `weight`，实现 `questionPoints`（`assets/js/store.js:471`–`assets/js/store.js:475`）。题目编辑框留空即写 `null`（web/src/teacher/pages/bank/（Vue 题库页）+ assets/js/import.js（解析器）），列表标注「（继承题型）/（自定义）」（web/src/teacher/pages/bank/（Vue 题库页）+ assets/js/import.js（解析器））。

设 `B`=base、`h`=`halfRatio`、`w`=`wrongPenalty`、`f`=`fastBonus`：

| 判定 result | ratio | 公式 | 默认（h=0.5,w=0,f=0） |
| --- | --- | --- | --- |
| `correct` 答对 | 1（`RESULT_RATIO.correct`，`assets/js/store.js:25`） | B × 1 + f，**仅当本次标记抢答** | +B |
| `half` 部分正确 | **显式 ratio 优先**，否则 `settings.halfRatio` | B × ratio | 见下方"部分得分" |
| `wrong` 答错 | 0 | 0 − w | 0 |
| `skip` 跳过 | 0 | 0 | 0 |
| `manual` 手动 | 1 | 直接写 `points = delta`，**不走公式** | ±N |

`computePoints` 逐行摘要（`assets/js/store.js:558`–`assets/js/store.js:569`，表达式为等价简化写法）：

```js
var st = get().settings;                                    // store.js:559  读"当前"设置
if (opt.ratio 有值)        ratio = opt.ratio;               // store.js:561  显式指定优先
else if (result==='half')  ratio = st.halfRatio;            // store.js:562  回落 0.5
else                       ratio = RESULT_RATIO[result]||0; // store.js:563
var pts = num(opt.base, 0) * ratio;                         // store.js:565
if (result === 'correct') pts += num(opt.fast ? st.fastBonus : 0, 0); // store.js:566
if (result === 'wrong')   pts -= num(st.wrongPenalty, 0);             // store.js:567
return Math.round(pts * 100) / 100;                         // store.js:568  两位小数
```

**四舍五入**只在 `assets/js/store.js:568` 一处：保留 2 位小数、标准四舍五入。例：`B=3,h=0.4 → 1.2`；`B=5,h=0.5 → 2.5`。学生总分同样按两位小数收口（`assets/js/store.js:515`）。

`recordResult` 写入流程（`assets/js/store.js:605`–`assets/js/store.js:637`）：

| 步骤 | 说明 | 代码 |
| --- | --- | --- |
| 1 | 校验学生存在；取题目，`tierKey` 取传入值，否则取题目 `tier` | `assets/js/store.js:607`–`assets/js/store.js:610` |
| 2 | 定 `base`：显式传入 > 题目基准分 > 题型权重；未知 `result` 兜底为 `correct` | `assets/js/store.js:611`–`assets/js/store.js:614` |
| 3 | 组装流水，`ratio`(622) 与 `points`(623) 在此刻**快照** | `assets/js/store.js:615`–`assets/js/store.js:628` |
| 4 | 落库：试卷存在则进该试卷，否则进收集器；写日志「记分」并 `commit` | `assets/js/store.js:630`–`assets/js/store.js:635` |

## 5. 基准分快照：改权重不改历史

每条流水固定保存 `tier`（`assets/js/store.js:200`）、`base`（`assets/js/store.js:203`）、`ratio`（`assets/js/store.js:204`）、`points`（`assets/js/store.js:205`），所以事后改权重（`updateTier`）或改题目分值（`assets/js/store.js:840`）都不重算历史。断言见 `tests/logic.test.js:160`–`tests/logic.test.js:163`：基础题答对 3 分 → 权重改成 9 → 历史仍 3 分，新记录才 9 分。

### 综合表现（多维度评价，与"积分"是两件事）

**积分**（`score`）是课堂游戏分：按题型加权、可加可减，学生看得见、用来排名。
**综合表现**（`evaluate`）是**评价**：正确性 / 参与度 / 进步 三维加权（默认 60/25/15，可配置），
可下钻、失效维度自动重归一。两者**刻意分开** —— 调研里成熟产品的共识正是
"娱乐性积分与评价性数据必须物理隔离"（Kahoot 因速度计分被教师批评多年，
Wayground 要靠第三方专门写"别用 points 打分"）。

详见 [05 §5.3](05-学情分析与总结.md)。

### 部分得分（多答案题按命中比例）

**2026-10 改**：原来多答案题是两分法 —— 是正确答案的**子集**就给 `halfRatio`(0.5)、**多选一律 0 分**。
结果是得分与"答对了多少"完全脱钩（正确答案 ABCD 时）：

| 学生的选择 | 改前 | 改后 |
| --- | --- | --- |
| ABC（漏 1 个） | 5 | 7.5 |
| AB（漏 2 个） | 5 | 5 |
| **A（漏 3 个，只对 1/4）** | **5** | **2.5** |
| **ABCDE（4 个全对 + 多选 1 个）** | **0** | **7.5** |
| ABE（对 2 错 1） | 0 | 2.5 |

新规则（两侧同一口径，parity 逐字段比对）：

```
ratio = max(0, (命中数 − 误选数) / 正确选项总数)
```

- 单选与填空没有部分分空间（对 = 1、错 = 0），行为不变
- 教师手工判定「部分正确」时没有显式 ratio，仍回退 `halfRatio`
- 依据：`docs/research/评价算法与量规设计.md` §3.4（"按命中比例"与"答对减答错"两种通行规则的保守合并）

> ⚠️ 例外：`creditRate` 用**当前** `halfRatio` 重算（`assets/js/analysis.js:41`–`assets/js/analysis.js:42`），改系数会让历史得分率一起变，而积分不变（见 §11 第 3 条）。

## 9. 快捷加分是否计入正确率

统计总闸 `counts`（`assets/js/analysis.js:20`–`assets/js/analysis.js:24`）：

```js
if (!CI.store.isCountable(r)) return false;   // analysis.js:21  tier 非空且非 manual
if (r.source === 'quick' && settings(s).quickCountsAsAttempt === false) return false; // analysis.js:22
return true;                                  // analysis.js:23
```

| 开关 | 快捷流水（`source:'quick'`、带 `tier`、`result:'correct'`） |
| --- | --- |
| 计入（缺省 / `true`） | 进 `attempts` 且进 `correct` → 每条等于该题型满分一次，会拉高得分率 |
| 只加分（`false`） | 不进 `attempts/correct/earned/base`，但 `points` 照进总分（`scoreOf` 只看 `points`，`assets/js/store.js:511`–`assets/js/store.js:513`） |

界面下拉文案即「计入（视为该题型答对一次）/ 只加分，不计入正确率」（web/src/teacher/pages/bank/（Vue 题库页）+ assets/js/import.js（解析器）–web/src/teacher/pages/bank/（Vue 题库页）+ assets/js/import.js（解析器））。学生端提交（`source:'student'`）**不受这个开关影响**：它既不是 `quick`，也自带题型快照，因此一律进 `attempts/correct/earned`（见 §6 第 5 条）。

## 11. 已知限制

1. **删除试卷会连带删除其流水**（`assets/js/store.js:1070`），不可恢复；收集器虽不出现在下拉框，但会被「全班归零 / 恢复初始」一并清空。
2. **题型权重与题目分值的改动只影响后续记录**（`assets/js/store.js:943`、`assets/js/store.js:840` 都不回写流水），历史 `base/points` 是快照。
3. **`halfRatio` 是例外**：`creditRate` 用当前系数重算（`assets/js/analysis.js:41`），调小它会让历史得分率下降而积分不变——「积分高、得分率低」并不矛盾。
4. **快捷加分恒为「答对」**：想「只加 2 分但不计答对」只能用卡片手动分（`tier` 为空、不进题型统计），或关掉 `quickCountsAsAttempt`。
5. **手动 ±分与归零不计入题型统计**（`tier:''`，`assets/js/store.js:645`、`assets/js/store.js:663`；判定 `assets/js/store.js:489`），但计入总分。
6. **快捷/手动分可能落进正式试卷**：只要当前选了试卷，`quizId` 就是该试卷（web/src/teacher/（Vue 教师端各页面）、`assets/js/rollcall.js:357`），该卷「累计得分」不再等于本卷题目得分。
7. **流水不保存 `fastBonus/wrongPenalty` 快照**，只有 `points` 与 `base/ratio`（`assets/js/store.js:203`–`assets/js/store.js:205`），事后只能由 `points - base` 反推抢答。
8. **点名判定没有抢答入口**（`assets/js/rollcall.js:338`），批量加分同样没有（web/src/teacher/pages/quiz/（Vue 组卷页）），只有组卷答题页会询问（web/src/teacher/pages/quiz/（Vue 组卷页））。
9. **删除学生不删除其流水**（`assets/js/store.js:817`–`assets/js/store.js:826`）：流水留在试卷 `records` 里，不再计入任何分数与排行，但继续占用 localStorage；组卷流水表显示「（已删除）」（web/src/teacher/pages/quiz/（Vue 组卷页））。
10. **`clearRecords` 有 API 没界面**（`assets/js/store.js:707`，无调用方），误用即不可恢复。
11. **撤销是全局最近一条**，不区分试卷与学生（`assets/js/store.js:674`–`assets/js/store.js:681`）；`at` 相同时取遍历中较靠后的一条，连点很快时可能撤到别人的记录。
12. **薄弱判定按题型且要求样本量**（`assets/js/analysis.js:110`）：每题型只答 1 次不会标薄弱，`levelOf`（`assets/js/analysis.js:149`）只给「优秀/良好」这类粗结论。
13. **`resetAllScores` 只豁免 v1 迁移卷**（`assets/js/store.js:1149`），收集器里的手动分与快捷分会被一起清空；需要留档请先「导出全部数据（备份）」。
14. **学生端提交依赖课堂开关与去重判定**：`runtime.accepting` 为假时学生端不能提交（`assets/js/student.js:293`）；同一试卷内同题同人重复提交会被 `answeredAlready` 静默忽略（`assets/js/classroom.js:141`）—— 学生"交了两遍只算一遍"是设计行为。主观题的 `pending` 队列不是流水，判定前不计分、丢弃即无痕（`assets/js/classroom.js:237`），且「全班归零」不会清它（`assets/js/store.js:1147`）。
