# 06 · 点名系统

课堂随机点名 + 点完立刻判分 + 点名数据进入学情统计。点名相关功能在 v3 中**行为未变**（只多了动画期护栏，见 §5.5），但周边文件有改动、行号已整体位移；本文只描述 v3 代码的真实行为，每条结论都可用 `路径:行号` 回查。

**术语**（与其它文档一致）：题型 `tier`（基础题 3 / 拔高题 5 / 扩展题 8 / 提升题 10 分，`assets/js/store.js:28-33`）；判定 `result`：`correct` 答对 / `half` 部分正确 / `wrong` 答错 / `skip` 跳过（`assets/js/store.js:25-26`）；流水 `record`：一次记分记录，学生积分 = 全部流水 `points` 之和（`assets/js/store.js:506-519`）；当前学生 `runtime.sid`、当前题 `runtime.qid`、当前试卷 `runtime.quizId`（`assets/js/store.js:161`）；轮次池 `roundPool`：均匀模式下"本轮还没被点到"的学生 id 列表（`assets/js/store.js:156`）。代码分工：算法 `candidates/pick/applyPick` 在 `assets/js/rollcall.js:41,69,114`，UI 在 `:137-383`，状态写入在 `assets/js/store.js:1082-1145`。

## 1. 需求与设计目标

- **课堂随机点名 + 点完立刻判分**：三种模式统一入口 `pick()`，返回 `{sid,name,mode,note,candidateCount,newRound,pool,round}`（`assets/js/rollcall.js:69-111`）；定格后 `runtime.sid` 即被点学生，四个判分按钮直接对其调用 `recordResult`（`assets/js/rollcall.js:119,330-348`）。
- **点名数据进入学情**：`calledCount()` 由 `rollcall.history` 派生，进入个人总结与全班覆盖率（`assets/js/store.js:533-536`、`assets/js/analysis.js:118,313`）。
- **一轮内不重复 / 可撤销**：均匀模式用"不放回"轮次池（`assets/js/rollcall.js:83-95`）；点名历史与积分流水分离，撤销点名不影响已记积分（`assets/js/store.js:1128-1137`）。
- **两条硬约束**：算法与 UI 分离，纯逻辑可在 Node 中直接跑（`assets/js/rollcall.js:18-121`、`tests/logic.test.js:28`）；`pick()` 不写状态、`applyPick()` 才落库（`assets/js/rollcall.js:65-68,114-121`）。**点名 ≠ 记分**——`rollcall.history` 只记"谁在何时被点"，判定结果靠时间戳关联推导（第 6 节）。

## 2. 三种点名模式（`rollcall.mode`）

| mode | 候选基础 | 不放回 | 维护轮次池 | 自增 round | 适用 |
| --- | --- | --- | --- | --- | --- |
| `even` 轮次池·均匀点名（默认 `store.js:151`） | 候选 ∩ 本轮池；池空时用全部候选重建 | 是 | 是 | 池空且历史非空时 +1 | 想让全班一轮内都被点到 |
| `random` 纯随机 | 全部候选 | 否 | 否（`pool=null`） | 否 | 完全随机、允许重复 |
| `least` 最少被点优先 | 全部候选 | 否 | 否（`pool=null`） | 否 | 补齐被点次数少的学生 |

### 2.1 `even` — 轮次池均匀点名

```text
pickEven(rc, list):                       # list = candidates() 的结果
    poolIds = rc.roundPool                # 本轮还没被点到的 id
    inPool  = list ∩ poolIds              # 只在本轮池里选（rollcall.js:85）
    if inPool 为空:                        # rollcall.js:86-92
        newRound = (rc.history 非空 and poolIds 为空)
        inPool = list; note = newRound ? '本轮已全部点到，开启新一轮' : '新一轮开始'
        if newRound: round = rc.round + 1
    chosen = rand(inPool)                 # rollcall.js:93
    pool   = inPool \ {chosen}            # 不放回，点完为止，下一轮自动重置（rollcall.js:95）
```

- **候选构建与轮次推进**：候选 = `poolIds ∩ candidates()`（`:85`），所以范围 / 已作答 / 防连点过滤同样生效；每次把 `chosen` 从 `inPool` 剔除后写回 `roundPool`（`:95` → `:117` → `assets/js/store.js:1110-1116`），下一次只从剩余池成员里抽，空数组也是真值、"点完最后一人"会把空池写回并触发下一轮。**何时开启新一轮**：`roundPool` 为空时若 `history` 非空则判为新一轮、`round` 加一（`:88-91`）；首次点名（`history` 为空）只提示"新一轮开始"、`round` 保持 1。单测覆盖：连点 5 次得到 5 个互不相同的 `sid`，第 6 次进入新一轮（`tests/logic.test.js:315-323`）。

### 2.2 `random` — 纯随机

```text
pickRandom(list):
    chosen = rand(list); note = '纯随机模式'   # rollcall.js:97-98
    pool   = null                             # 不维护轮次池：applyPick 不调 setRoundPool（:117）
```

该模式不写 `roundPool`、也不改 `round`（`assets/js/rollcall.js:117`）。

### 2.3 `least` — 最少被点优先

```text
pickLeast(state, list):
    counts = { st.id : calledCount(state, st.id) for st in list }   # rollcall.js:79
    least  = [st in list where counts[st.id] == Min(counts)]        # rollcall.js:80
    chosen = rand(least)                                            # 平局随机，rollcall.js:81
```
`calledCount` = `history` 中该 `sid` 的条数（`assets/js/store.js:533-536`），是**全量历史**口径、不随轮次清零，因此该模式天然避开刚点过的人（`tests/logic.test.js:326-331`）。

## 3. 候选池过滤规则（`candidates`）

```text
candidates(state, opts):                                  # assets/js/rollcall.js:41
    list = studentsOf(state, opts.scope ?? rc.scope ?? 'all') 过滤 (stu.active !== false)   # :44-45
    if (opts.excludeAnswered ?? rc.excludeAnswered) and quizId and qid:
        list = [st in list where not answeredAlready(state, quizId, qid, st.id)]   # :50-54
    if num(opts.recentExclude ?? rc.recentExclude, 0) > 0:
        skip     = history[-n:].map(h => h.sid)           # :28-30, :58
        filtered = [st in list where st.id not in skip]   # :59
        if filtered 非空: list = filtered                 # 兜底：全被排除则放弃该约束  :60
```

| 过滤项 | 规则 | 依赖 | 依据 |
| --- | --- | --- | --- |
| 范围 scope / 在册 active | `'all'` 取全班，否则取该队伍 id（`studentsOf` 对 `undefined`/`'all'` 不过滤）；只保留 `active !== false`（`undefined` 视为在册，因归一化默认 `true`） | `rollcall.scope`、`student.active` | `assets/js/store.js:528-531,258`、`assets/js/rollcall.js:44-45` |
| 排除已作答 | 排除"当前题已作答"的学生；**必须同时有 `quizId` 与 `qid`**，缺一则整条约束不生效 | `runtime.quizId` + `runtime.qid` | `assets/js/rollcall.js:47-54` |
| 防连点 | 不重复最近 N 次被点到的学生；**过滤后为空时自动放弃该约束** | `rollcall.history` 末尾 N 条 | `assets/js/rollcall.js:56-61` |

`answeredAlready(s, quizId, qid, sid)` 的判定范围是**该试卷内**是否存在同一题、同一学生的流水（`assets/js/store.js:543-547`）：跨试卷的作答不算"已答"，同一试卷内无论 `source` 是 `quiz`/`quick`/`rollcall`/`student` 都算。兜底逻辑的后果：`recentExclude` 是软约束（宁可重复也不空池），`excludeAnswered` 是硬过滤（真会把候选清空）；全班都答完当前题时 `pick()` 返回 `null`，舞台显示"无可点名学生 / 请检查名单、范围或'排除当前题已作答'设置"（`assets/js/rollcall.js:296-300`）。

## 4. 状态与持久化

### 4.1 `rollcall` 对象字段

| 字段 | 默认值 | 含义 | 修改入口 |
| --- | --- | --- | --- |
| `mode` / `scope` | `'even'` / `'all'` | `even`/`random`/`least`；`'all'` 或队伍 id | `#rcSetup` 模式与范围下拉（`rollcall.js:151,153-157`） |
| `excludeAnswered` | `true` | 是否排除当前题已作答 | `#rcSetup` 复选框（`rollcall.js:164-165`） |
| `recentExclude` | `1` | 不重复最近 N 次被点到的学生，下拉只给 0/1/2/3 | `#rcSetup` 防连点下拉（`rollcall.js:159-163`） |
| `history` | `[]` | 点名记录数组，见 4.2 | `addRoll` / `removeRoll` / `resetRolls` |
| `roundPool` / `round` | `[]` / `1` | 本轮尚未被点到的学生 id / 第几轮 | `setRoundPool(pool, round)`（仅 `even` 模式） |

默认值定义在 `assets/js/store.js:150-158`；`normalize()` 补齐缺失字段、把非数组的 `history`/`roundPool` 置空、过滤掉已不存在的学生 id、`round` 兜底为 1（`assets/js/store.js:237-238,284-287`）。

### 4.2 `history` 条目结构、上限与持久化

条目为 `{ id, sid, at, quizId, qid }`（`assets/js/store.js:1086-1090`）：`id` 是 `uid('rl')`，供 `removeRoll` 定位；`sid` 是被点学生；`at` 为 `Date.now()`，判定关联与列表时间都用它；`quizId`/`qid` 是点名时的运行时上下文快照（由 `applyPick` 传入，`assets/js/rollcall.js:118`），可能为 `null`。**2000 条上限**：超过时从头部删除最旧的（`assets/js/store.js:1092`）。整份 `state`（含 `rollcall`）序列化进 `localStorage` 键 `ci_data_v2`（`assets/js/store.js:19,353-366`）；`addRoll` 走 `tx → commit`，会 `rev++`、落盘并触发 `change`（`assets/js/store.js:431-441,416-423`）；`setRuntime` 只保存并以 `silent` 语义广播、不写日志（`assets/js/store.js:1139-1145`）。

### 5.1 开始点名与滚动动画

按钮 `admin.html:83` 与空格键都调用同一个 `CI.rollUI.spin()`（`assets/js/rollcall.js:292-327`）：

```text
spin():
    if spinning: return                     # 防重入，:293
    result = pick(state, {})                 # 先定结果，:295
    if not result: 舞台显示"无可点名学生"+提示; return   # :296-300
    list = candidates(state, {}); spinning = true; ticks = 0; total = 16   # :303-304,307
    setInterval(70ms):                       # :309-326，16 帧 × 70ms = 1120ms
        ticks += 1; 舞台显示 rand(list).name + "抽取中…"
        if ticks >= total:
            spinning = false; applyPick(result); stage.classList.add('rc-flash')  # 第 16 帧写状态 :319-322
            setTimeout(移除 rc-flash, 600); render()                              # 定格闪烁 :323-324
```

动画期间 `renderStage` 直接返回、不覆盖滚动内容（`assets/js/rollcall.js:174`）；点名成功后 `applyPick` 依次写轮次池 → 追加历史 → 更新 `runtime.sid`（`assets/js/rollcall.js:114-121`）。

### 5.2 判分按钮与题型快捷按钮

判分按钮显示"标签 + 预计得分"，得分由 `computePoints` 现算（`assets/js/rollcall.js:211-216`、`assets/js/store.js:558-569`）：

| 按钮 | `result` | CSS 类 | 预计得分（默认设置下） |
| --- | --- | --- | --- |
| 答对 | `correct` | `btn-plus` | `base × 1`（点名路径不传 `fast`，**不触发抢答加分**） |
| 部分正确 | `half` | `btn-half` | `base × halfRatio`（默认 0.5） |
| 答错 / 跳过 | `wrong` / `skip` | `btn-minus` / `btn-skip` | `−wrongPenalty`（默认 0，按钮显示 `+0`）/ `0` |

`base` 取当前题的实际基准分 `questionPoints`（题目自定义 `points` 优先，否则题型权重，`assets/js/store.js:471-475`）；没有当前题时取第一个题型的权重（`assets/js/rollcall.js:202-205`）。题型快捷按钮每个 `tier` 一个，点击 `quick(key)` → 以 `result='correct'`、`qid=null`、`source='quick'` 记分，基准分固定取该**题型权重**而非题目自定义分（`assets/js/rollcall.js:218-221,351-359`）。

### 5.5 动画期护栏（v3 修复：不再记到上一位学生头上）

`spinning` 在起滚前就置 `true`（`assets/js/rollcall.js:304`），而 `runtime.sid` 要到**第 16 帧**才由 `applyPick` 写入（`assets/js/rollcall.js:319-322` → `:119`）。在 1120ms 窗口内：

- `judge(result)` 与 `quick(tierKey)` 都先查 `spinning`，命中则 `alert` 并 `return null`（`assets/js/rollcall.js:333`、`assets/js/rollcall.js:354`）；
- 快捷键 `1`~`4` 走的正是 `judge()`，所以键盘路径同样被拦（`assets/js/rollcall.js:378-381`）；
- 等价于把"动画期间的判分"整体变成空操作：既不写 `recordResult`，也不改 `runtime.sid`，因此不会出现"分记到上一次被点学生头上"。

浏览器冒烟测试固定了这条行为：`check(CI.rollUI.judge('correct') === null, '动画未定格时判分被拒绝（不会记到上一位学生）')`（`tests/smoke.html:125-126`），定格后再判分则正常记分（`tests/smoke.html:127-135`）。

## 6. 与计分的联动

`judge(result)` 直接调用 `recordResult`，写入字段如下（`assets/js/rollcall.js:338-346`）：

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `sid` / `qid` | `runtime.sid` 对应的学生 / `runtime.qid` 对应题目（无则 `null`，题目来自当前题） | `currentStudent()` 解析（`rollcall.js:132-135`） |
| `tier` | `q ? q.tier : tiers[0].key` | 无当前题时按第一个题型 |
| `quizId` | `runtime.quizId \|\| null` | 为空则进"快捷记分"收集器（`store.js:572-582,630-631`） |
| `source` / `by` | `'rollcall'` / `'rollcall'` | 点名判分的流水标记 |
| 无当前题 / 无当前试卷 | `tier`=`tiers[0].key`（默认基础题，权重 3）算 `base`、`qid=null`；`quizId` 为空时进"快捷记分（课堂零散加减）"自动收集试卷 | `store.js:611-613,572-582,630-631` |

### 6.1 两条记分链路：点名判定 vs 学生端提交

v3 里点名不再是课堂判分的唯一入口：⑦ 课堂协同页签允许学生端提交作答（详见 `docs/04-题库与组卷答题.md` §8.2）。两条链路最终都落到同一个 `store.recordResult`（`assets/js/store.js:605-637`），因此积分、队伍分与学情统计口径完全一致，仅流水标记不同：

| 维度 | 老师点名判分（本文） | 学生端提交（⑦ 课堂协同） |
| --- | --- | --- |
| 触发 | ③ 点名定格后点四个按钮 / 按 `1`~`4` | 学生端 `{kind:'answer', …}` 经枢纽转发 → `CI.classroom.handleCmd` |
| 判定人 | 老师 | 客观题由 `CI.grade.auto` 自动判，主观题老师点「答对/部分对/答错/跳过」 |
| 写分调用 | `recordResult({source:'rollcall', by:'rollcall'})`（`assets/js/rollcall.js:338-346`） | `recordResult({source:'student', by:'student'})`（`assets/js/classroom.js:169-178`）；主观题确认时 `by:'classroom-confirm'`（`assets/js/classroom.js:210-219`） |
| 学生归属 | `runtime.sid`（定格第 16 帧时写入） | 命令里的 `sid` → 当前学生（须同队）→ 该队第一个成员（`assets/js/classroom.js:56-65`） |
| 重复作答 | `confirm` 后可再记一次（`assets/js/rollcall.js:335-337`） | **静默忽略**，只写一条「重复提交，已忽略」实时流（`assets/js/classroom.js:138-145`） |
| 抢答加分 | 点名路径不传 `fast`，不触发（`assets/js/rollcall.js:338-346`） | 同样不传 `fast`（`assets/js/classroom.js:169-178`） |

**点名记录列表中判定结果的展示逻辑**（`renderHistory`，`assets/js/rollcall.js:253-277`）：

```text
hist = history[-40:].reverse()                       # 倒序，最多 40 条
for h in hist:
    rec = recordsOf(s, {sid: h.sid})                 # 该生全部流水，已按 at 升序
            .filter(r => r.at >= h.at and r.at - h.at < 300000)[0]   # 5 分钟窗内第一条
    judge = rec ? RESULT_LABEL[rec.result] + 得分 : '未判定'
```

即"该次点名后 5 分钟内的第一条流水"视为本次判定结果（`assets/js/rollcall.js:263-268`）；`recordsOf → allRecords` 保证升序，`[0]` 就是最早那条（`assets/js/store.js:478-486`）。这里**不按 `source` 过滤**，所以这 5 分钟内该生从其它入口（组卷页判分、题型快捷加分、手动加减分、**学生端自动判分**）产生的第一条流水也会被显示为该次点名的判定。

## 8. 典型课堂用法

**场景 A · 基础题全班轮一遍**：范围=全班、模式=轮次池均匀、防连点=最近 1 次、排除已作答=开；点名后按 `1`/`2`/`3`/`4` 判分并重复。`#rcStats` 的"本轮剩余"归零后，下一次点名自动进入新一轮（`rollcall.js:86-92`），单测证明连点 N 次得到 N 个互不相同的 `sid`（`tests/logic.test.js:315-323`）。

**场景 B · 拔高题只点强队**：把范围下拉切到目标队伍（`rollcall.js:151`）。注意改设置会清空轮次池（`store.js:1101`），且下一次点名会因"池空 + 历史非空"被判为新一轮、`round` 直接 +1（`rollcall.js:88-91`）——范围最好在课前设定，课中切换会让轮次计数跳变。

**场景 C · 避免连点同一人**：防连点设为"最近 2 次"或"最近 3 次"（下拉上限 3，`rollcall.js:160`）。该约束是软约束：候选恰好全部落在最近 N 条里时会静默失效（`rollcall.js:60`），人数很少时仍可能"还是同一个人"；想整轮不重复请用 `even`，想优先照顾被点少的人请用 `least`（`rollcall.js:78-82`）。

**场景 D · 点名未作答者优先**：先把某题设为当前题（`quiz.js:247-250`），保持"排除当前题已作答"勾选，然后连续点名：已答过该题的学生自动退出候选（`rollcall.js:50-54`、`store.js:543-547`），全员答完后候选为空，舞台提示"无可点名学生"（`rollcall.js:298-299`）。注意 v3 里学生端自己交的题同样算"已作答"，所以⑦页签开着时这一条会更快把人筛完。

## 9. 已知限制

1. **改范围/模式会清空轮次池、防连点只按"最近 N 次"**：`setRollSettings` 无条件把 `roundPool` 置空（`store.js:1101`），下一次 `even` 点名还会因"池空 + 历史非空"把 `round` 加一（`rollcall.js:88-91`），即使上一轮并未点完；防连点窗口上限只有 3（`rollcall.js:160`）且只取 `history` 末尾 N 条（`rollcall.js:28-30`），排除后为空时会静默放弃该约束（`rollcall.js:60`）。
2. **已作答过滤是硬过滤、没有兜底**：全员答完当前题就无人可点（`rollcall.js:296-300`）；且 `roundPool` 中因已作答被过滤掉的学生不在新 `pool` 里（`pool` 只由 `inPool` 派生，`rollcall.js:95`），本轮不再被点，要等下一轮重建池。
3. **记录只在本机，多设备同时点名不会互相同步**：点名历史随整份状态存在浏览器 `localStorage`（键 `ci_data_v2`，`store.js:19,353-366`）；教师端虽会向枢纽推全量快照、也能收 `state`/`dump`（`sync.js:4-8,107-108,115-119`），但收到的快照只用于状态提示、**不会自动覆盖本机数据**，两台主控台各自维护独立的 `history` 与积分，大屏只被动接收榜单快照；换设备或清缓存前请先"导出全部数据"（`admin.html:128`）——或让新设备在枢纽提示「载入课堂数据」时确认恢复（`admin.js:524-534`）。
4. **撤销单条点名不回填轮次池**：`removeRoll` 只删历史条目（`store.js:1128-1137`），该生本轮不会再被抽到、`round` 不回退，已记积分需另行撤销流水。（动画期间的判分拒绝**已不是限制**，而是 v3 的护栏，见 §5.5。）
5. **判定结果是启发式关联**："点名后 5 分钟内该生第一条流水"（`rollcall.js:264-266`）没有 `record → roll` 外键，5 分钟内其它途径的记分（含⑦页签的学生端自动判分）会顶替显示为该次点名的判定。
6. **删除学生/试卷会追溯改写历史**：删学生清空其点名历史与池内 id（`store.js:822-823`），删试卷删掉带该 `quizId` 的历史（`store.js:1072`），`calledCount` 与学情数字随之变化；点名判分也**不触发抢答加分**（`judge` 不传 `fast`，`rollcall.js:338-346`；对比 `quiz.js:363-366`）。
7. **`pick()` 的 `note`/`candidateCount`/`newRound` 不展示**：仅用于单测与调试（`tests/logic.test.js:321-322`），界面看不到模式说明文字；`quickFor` 虽已导出但当前代码没有调用点（`rollcall.js:362-368,387`）。`history` 超过 2000 条丢最旧（`store.js:1092`），列表只显示最近 40 条（`rollcall.js:257`）；点名判分产生的流水在大屏只能通过 `meta.recent` 最近 8 条滚动条间接看到（`sync.js:280-289`、`index.html:271-277`）。
