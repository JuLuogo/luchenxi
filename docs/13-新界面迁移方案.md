# 13 · 新界面（Vue 3）迁移方案与进度

> **2026-10 更新：界面已统一到 Vue。** 客户端（Tauri）与网页版（枢纽托管）加载的都是
> `web/dist` 构建产物，入口文件名沿用旧约定（`admin.html` / `student.html` / `index.html`），
> 所以 URL 一个都没变。旧版零构建页面（仓库根的三个 HTML + `assets/js` 里的渲染层）
> **只保留在 `/legacy/*` 供旧 e2e 使用，下一轮连同旧 e2e 一起删除**。
>
> 三处来源都指向同一份产物：
> - 客户端：`scripts/sync-ui.mjs` 把 `web/dist` 拷进 `apps/<app>/ui/`（`frontendDist="../ui"`）
> - 网页版：两个枢纽的 `/`、`/join`、`/stage` 直接服务 `web/dist`
> - 大屏：`index.html` 也是 Vue 入口（按课堂环节切四屏）
>
> 守卫：`tests/ui-vue.test.mjs`（三入口冒烟 + 一条流程级用例）已进 CI。
> 它一上线就抓到一个真 bug：概览页把 `CI.analysis.counts(s, r)`（逐条流水的判定函数）
> 误当汇总调用，一进首页就抛异常 —— 而此前 **Vue 界面零端到端覆盖**。

> 起因：v4 换了外壳（Tauri + 本地 SQLite + 内置枢纽），但界面还是 v3 的**零构建单页铺开式**——
> `admin.html` 一个文件里塞了 7 个 tab，所有控件平铺在一屏，题库、组卷、点名、学情混在一起。
> 本文记录重写方案、页面清单、进度与切换步骤。

## 1. 技术选型（依据 npm registry 实查，2026-10）

| 用途 | 选择 | 版本 | 为什么 |
| --- | --- | --- | --- |
| 框架 | Vue 3 + Vite 7 | vue 3.5 / vite 7.3 | 组合式 API 适合把"一页只做一件事"拆开；构建产物可直接给 Tauri 与枢纽托管 |
| 路由 | vue-router 4（**hash 模式**） | 4.5 | Tauri 里页面来自自定义协议，history 模式刷新会 404；hash 最稳 |
| 状态 | Pinia | 3.x | 只做一层薄桥接：订阅 `CI.store` 的 `change` 事件，把领域层状态映射成响应式 |
| 教师端组件库 | **Element Plus** | 2.14.7（2026-09-30 仍在发版） | 表格/表单/弹窗最全，中文文档最厚；同类里 `ant-design-vue` 最后发版停在 **2024-11-11**，不适合新项目 |
| 学生端组件库 | **Vant** | 4.10.2（未压缩 5.9 MB，同类最小） | 移动端最成熟：答题卡、Popup、Tabbar、Toast 现成；`@nutui/nutui` 稳定版更新停滞（最新是 beta） |
| 大屏 | 手写（深色） | — | 大屏只读、样式特殊，引组件库不划算 |

**关键决定：不重写业务逻辑。** `assets/js/*`（store / grade / classroom / sync / net / analysis / rollcall）
已被 1243 项断言覆盖，Vue 层通过 `web/src/shared/bridge.js` 按原顺序 import 复用它们，
只替换旧的那批 `render()` 渲染函数。这样"换界面"不会把判分、同步、存储这些已经验证过的行为改坏。

## 4. 与旧界面的关系（切换步骤）

第一批**不动**旧页面：`/admin.html`、`/join`、`/stage` 仍是 v3 界面，两条 e2e（78 + 65 项）继续保证它可用。
第二批完成后按下面四步切换，做完旧界面即可删除：

1. `scripts/sync-ui.mjs` 改为：先 `npm --prefix web run build`，把 `web/dist` 复制进 `apps/*/ui`；
   两个客户端的 `tauri.conf.json` 把窗口 url 指到 `admin.html`（教师端）/ `student.html`（学生端）。
2. 枢纽静态托管切到 `web/dist`（把现在的 `/next/` 分支提到根路径），`/join`、`/stage` 别名保持不变。
3. 端到端测试改驱动新界面：用 `data-testid` 属性 + 路由 hash 定位（旧 e2e 依赖的元素 id 会消失）。
   领域层测试（logic/db/storage/protocol/hub-spec…）**不需要改**，因为它们用的是 `CI.*` API 而不是 DOM。
4. 删除 `admin.html`、`student.html`、`index.html` 与 `assets/js` 里的旧渲染层（`CI.*UI`、`CI.admin`），
   同时更新 `tests/dom-check.js`（它现在校验旧脚本顺序）与文档里的截图。

## 5. 界面质量要求（第一批已落实）

- **一页只做一件事**：题库拆成 5 个页面（列表 / 新建 / 导入 / 题型 / 标签），不再和记分、点名混在一屏。
- **左侧分级侧边栏**：教学管理 / 题库中心 / 试卷中心 / 数据分析 / 系统设置 五组，当前页高亮，可折叠。
- **顶栏固定全局信息**：课程名、房间号、同步状态、存储后端（异常转红）、复制学生端地址、打开大屏、快捷键 `?`。
- **键盘快捷键**：`Alt+1..6` 跳转主要页面；点名页 `1/2/3/4` 判分；课堂协同页空格公布答案。
- **危险操作二次确认**：清空分数、恢复初始状态、批量删除、导入覆盖都明确提示影响范围。
- **判分风险前置**：题目列表对有判分问题的题标红，新建/导入两处都在保存/导入前调用
  `CI.grade.validateQuestion` 列出风险（旧版只在导入时提示过一次）。

## 7. 能力评价：按题型雷达 + 综合评级（第二批新增）

需求：题库分了基础/拔高/扩展/提升等题型，学生答对后应当能看出"**各题型能力强弱**"，
类似游戏里的能力雷达（"六边形战士"），并给出**个人评价与小组评价**。

### 7.1 算法（在领域层 `assets/js/analysis.js`，被 `tests/logic.test.js` 覆盖 31 项断言）

| 概念 | 口径 |
| --- | --- |
| 每条轴（一个题型） | `creditRate`：答对 100%、半对按 `halfRatio` 折算 —— **与加分口径一致** |
| 掌握度 `mastery` | 只在"已作答题型"上按**题型权重**加权平均（拔高题做对更值钱） |
| 综合分 `overall` | `mastery × 覆盖系数(0.6~1.0)` —— 只答过 1 个题型不会显示成 100 分 |
| 覆盖率 `coverage` | 已作答题型 / 全部题型 |
| 均衡度 `balance` | `100 - (最高轴 - 最低轴)`；只答过 1 个题型时为 `null`（无意义） |

评级从最理想往下判定，第一个命中即采用：

| 档 | 标签 | 条件 |
| --- | --- | --- |
| S | 六边形战士 | 覆盖 100% 且 最低轴 ≥ 80% 且 均衡度 ≥ 10 |
| A | 全面发展 | 覆盖 ≥ 75% 且 最低轴 ≥ 60% |
| B+ | 偏科尖子 | 最高轴 ≥ 85% 且 最低轴 < 50% |
| A- | 学有余力 | 综合分 ≥ 80 |
| B | 稳步提升 | 综合分 ≥ 60 |
| C | 基础待巩固 | 综合分 ≥ 40 |
| D | 需要重点辅导 | 其余 |
| — | 样本不足 | 作答次数 < `settings.minSample`（默认 2） |

评语自动生成：列出最强/最弱题型与百分比，再按评级给一句建议（如"先把短板补到及格线，总分涨得最快"）；
各轴接近时不硬凑"强项/短板"，会直接说"掌握度接近"。

### 7.2 界面位置

- **学情分析页顶部**：`AbilityPanel.vue` —— 雷达图（当前对象 + 全班平均对比线）、评级大卡（S/A/B… + 综合分 + 覆盖率 + 均衡度 + 作答次数）、逐题型进度条、评语（可一键复制）。
- **综合评价总览表**：队伍在前、学生按综合分排序，列出评级、覆盖率、均衡度、最强/最弱题型与评语；点任意一行切换雷达。
- **排行榜页**：个人榜与队伍榜各加一列「能力画像」徽章。

> 数据来源：`CI.analysis.ability(state, {sid|teamId})` 与 `CI.analysis.abilityBoard(state)`；
> 旧版界面未使用（不影响），网页版/客户端都能用同一份口径。

## 8. 大屏按"课堂环节"切换（第二轮新增）

大屏是教室里最主要的展示窗口，**不同环节该显示不同内容**——这是按需求重做的核心。

### 8.1 课堂环节是同步数据，不是界面状态

领域层新增 `CI.classroom.setPhase()` / `phase()`，四个环节写进 `runtime.phase`，
随快照 `meta.phase` 广播给大屏与学生端（`assets/js/classroom.js`）：

| 环节 | key | 大屏显示 | 学生端 |
| --- | --- | --- | --- |
| 待机 | `idle` | 房间号 + 学生端二维码 + 已入座队伍 | 选小组入座 |
| 随机点名 | `rollcall` | **被点到的同学姓名占满屏幕**（含队伍、今天被点次数） | 显示"被点名"状态 |
| 出题答题 | `question` | 题干 + 选项 + 抢答榜 + 当前积分 | 可作答、可抢答 |
| 点评总结 | `review` | **各队答对情况 + 能力雷达 + 自动评价** | 看自己/其他队答对多少 |

规则：出题环节自动带上第一题并开始接收作答；点评环节停止接收；点名环节收起答案；
没有题目时"出题"会退回待机。教师端「课堂协同」页顶部一键切换（点名环节会顺手抽一位同学，大屏立刻有内容）。

### 8.2 快照里新增的大屏数据

`CI.classroom.metaPayload()` 现在额外带出：

- `phase` / `phaseLabel`：当前环节
- `sid` / `sidName` / `sidTeamName` / `sidCalled`：当前被点学生（点名屏用）
- `teamStats`：全班 + 每队 { 答对数、作答数、加权得分率、总分 }（点评屏与"其他队答对多少"都用它）
- `ability`：全班 + 每队 + 每生的**能力雷达数据与评级评语**（点评屏直接用，不重算）

### 8.3 学生端（Vant）

- **入座**：大按钮选小组；可手输教师机地址（只写 IP 会自动补 8080）、测试连接、组网引导。
- **答题**：选题（多选自动识别）、填空输入、主观题文字作答；提交后显示"已提交"；公布答案后显示正确答案。
- **抢答**：橙色大按钮，抢到有反馈。
- **分数看板**：我们组总分/人数、**我答对几道 / 得分**、能力画像徽章、**其他队答对多少 + 全班合计**。
- **我们组**：组员列表（谁答对几道、多少分）、选谁作答（老师点名时按这个报）。
- **公屏模式**：`?view=board` 放大字号，适合平板挂墙上。

> 复用策略：学生端领域层沿用 `assets/js/student.js`（连接/入座/提交/抢答/快照解析），
> 只把渲染换成 Vue。为此给它加了 `CIStudent.init()/on()/state()` 三个接口，
> 并让 `$()` 在旧 DOM 缺失时返回"哑元素"——这样旧 student.html 不受影响，新界面也不报错。

## 9. 设计参考：从成熟课堂产品里借了什么（第三轮新增）

做界面时参照了几款成熟产品，只借"经过验证的模式"，不照搬视觉：

| 参考产品 | 借用的点 | 落在哪里 |
| --- | --- | --- |
| **Kahoot** | 浅色底 + **超大题干** + **四色选项块（红▲ / 蓝◆ / 黄● / 绿■）**；待机页超大二维码与房间码 | 大屏"出题作答"与"待机"两屏 |
| **班级优化大师（希沃）** | **置顶光荣榜实时刷新**、随机抽选、**多维度评价矩阵**（不只分数，看题型维度） | 大屏"点评总结"、学情分析的能力雷达、随机点名页 |
| **ClassDojo** | 大色块徽章、超大点击区域、鼓励式文案 | 学生端按钮与徽章、能力评级文案 |
| **shadcn / Radix 体系** | 中性色阶、1px 细边框、柔和阴影、统一圆角与留白、键盘提示样式 | 教师端与三端共用的设计令牌 |

参考来源：

- Kahoot 的产品形态（浅色大厅 + 四色选项块）是公开且被广泛模仿的课堂竞答范式

### 9.1 落地方式：设计令牌 + 浅色大屏

- 新增 `web/src/styles/tokens.css`：中性色阶、品牌/语义色、**Kahoot 四色**、圆角与阴影阶、字号阶，
  三端入口都引入，保证教师端 / 学生端 / 大屏视觉同源。
- **大屏改为浅色主题**（原先深色）：投影与教室电视上浅色更清楚、不反光，配合高对比大字与四色块，
  最后一排也能看清；雷达图同步改为浅色（白底、灰网格、彩色数据面）。
- 教师端在 Element Plus 之上叠加一层现代外观：卡片圆角与细边框、表头更轻、按钮去重阴影、
  空状态与说明文案统一到中性色阶。
- 学生端保留 Vant 的移动端手感，改用统一令牌：更大的点击区域、更清晰的分数与徽章层级。

> 取舍：没有引入新的组件库（Element Plus 2.14 / Vant 4 都是活跃版本），
> 而是把"设计语言"统一到一套令牌上——换库的收益小于回归风险，这一点在提交前已由 19 步本地 CI 验证。
